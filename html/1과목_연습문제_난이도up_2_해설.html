Q1. 업무에서 도출되는 엔터티 중, 기본 엔터티로부터 발생하며 업무의 중심적인 역할을 하고, 데이터 양이 많으며 다른 행위 엔터티를 파생시키는 '중심 엔터티(Main Entity)'의 예시로 가장 적절한 것은?
  • ① 사원, 부서
  • ② 주문, 계약
  • ③ 주문상세내역, 접속로그
  • ④ 공통코드, 우편번호
정답: ② 주문, 계약
① 사원, 부서, 코드는 업무에 원래 존재하는 기본 엔터티입니다.
② 주문, 계약, 예금원장은 기본 엔터티에서 파생되어 업무의 중심이 되는 중심 엔터티입니다.
③ 주문상세, 접속로그는 중심 엔터티로부터 빈번하게 발생하는 행위 엔터티입니다.
⭐️ 심화 개념
Q2. 식별자 관계(Identifying Relationship)와 비식별자 관계(Non-Identifying Relationship)에 대한 설명 중 **가장 옳지 않은** 것은?
  • ① 식별자 관계는 부모의 주식별자를 자식의 주식별자로 상속받는다.
  • ② 비식별자 관계는 부모의 주식별자를 자식의 일반 속성으로 상속받는다.
  • ③ 자식 엔터티가 부모 엔터티의 생명주기에 강하게 종속될 때는 비식별자 관계를 맺는 것이 바람직하다.
  • ④ 식별자 관계로만 지속적으로 모델링을 진행하면 자식 엔터티의 주식별자 속성 수가 점점 늘어나 조인(Join)이 복잡해질 수 있다.
정답: ③
부모가 삭제되면 자식도 존재할 수 없는 '강한 종속성'을 가질 때는 부모의 PK를 자신의 PK로 삼는 식별자 관계(실선)를 맺는 것이 바람직합니다. 비식별자 관계는 독립적인 생명주기를 가질 때 사용합니다.
Q3. 정규화 과정 중, "모든 결정자가 후보키(Candidate Key)가 되도록" 릴레이션을 분리하여 이상 현상을 제거하는 정규형은?
  • ① 제1정규형
  • ② 제2정규형
  • ③ 제3정규형
  • ④ BCNF
정답: ④ BCNF (Boyce-Codd Normal Form)
BCNF는 제3정규형을 만족하면서, 후보키가 아닌 결정자(일반 속성이 기본키의 일부를 결정하는 경우)를 제거하는 보다 엄격한 정규형입니다.
⭐️ 피터 첸 표기법
Q4. 피터 첸(Peter Chen)의 ERD 표기법에서 '이중 타원(Double Ellipse)'으로 표현되는 것은 무엇인가?
  • ① 약한 엔터티 (Weak Entity)
  • ② 다중값 속성 (Multi-valued Attribute)
  • ③ 파생 속성 (Derived Attribute)
  • ④ 관계 (Relationship)
정답: ② 다중값 속성
- 일반 속성: 타원
- 다중값 속성: 이중 타원 (하나의 속성에 여러 값이 들어갈 수 있음을 개념적으로 표현)
- 파생 속성: 점선 타원
- 약한 엔터티는 '이중 사각형'으로 표현합니다.
Q5. 외부 스키마와 개념 스키마 사이의 사상(Mapping)으로, 사용자 관점의 화면이나 응용 프로그램이 데이터베이스 전체 논리 구조의 변경에 영향을 받지 않도록 보장하는 독립성은?
  • ① 논리적 데이터 독립성
  • ② 물리적 데이터 독립성
  • ③ 구문적 데이터 독립성
  • ④ 의미적 데이터 독립성
정답: ① 논리적 데이터 독립성
논리적 독립성은 '외부적/개념적 사상'을 통해 응용 프로그램(외부 스키마)이 개념 스키마의 변경으로부터 독립되도록 보장합니다.
Q6. 인조 식별자(Artificial Identifier)를 도입하는 것이 바람직한 경우로 **가장 거리가 먼** 것은?
  • ① 본질 식별자를 구성하는 속성의 수가 너무 많아 복잡하여 조인 시 성능 저하가 우려될 때
  • ② 본질 식별자의 값이 자주 변경될 가능성이 높아 관리가 어려울 때
  • ③ 시스템에 의해 일련번호가 자동 생성되어 관리의 편의성을 높이고자 할 때
  • ④ 해당 엔터티의 인스턴스가 단 1~2개로 매우 적고 업무 규칙이 단순할 때
정답: ④
인조 식별자(예: 회원번호, 상품SEQ)는 본질 식별자(예: 이름+전화번호+주소)가 너무 길거나 복잡할 때 시스템적으로 추가하는 것입니다. 데이터가 1~2개뿐이라면 굳이 복잡한 인조 식별자를 만들 필요 없이 단순한 본질 식별자로도 충분합니다.
Q7. 데이터 모델링에서 '엔터티(Entity)'의 특징에 대한 설명 중 **가장 적절하지 않은** 것은?
  • ① 엔터티는 해당 업무에서 필요로 하고 관리하고자 하는 정보여야 한다.
  • ② 하나의 엔터티는 반드시 두 개 이상의 인스턴스 집합이어야 한다.
  • ③ 엔터티는 다른 엔터티와 최소 한 개 이상의 관계를 가져야 한다. (단, 공통코드 엔터티 등은 예외)
  • ④ 엔터티는 유일한 식별자가 없어도 데이터베이스에 테이블로 생성될 수 있으므로 식별자는 필수 요소가 아니다.
정답: ④
엔터티의 절대적인 원칙 중 하나는 **"반드시 유일한 식별자(Unique Identifier)가 존재해야 한다"**는 것입니다. 식별할 수 없는 데이터의 집합은 엔터티로 성립할 수 없습니다.
Q8. '파생 속성(Derived Attribute)'에 대한 설명으로 **가장 적절한** 것은?
  • ① 데이터의 정합성을 위해 가급적 많은 파생 속성을 정의하는 것이 좋다.
  • ② 다른 속성의 영향을 받아 계산되거나 유도되는 속성으로, 주로 데이터 조회 성능 향상을 위해 사용된다.
  • ③ 업무에서 원래부터 존재하는 가장 본질적인 속성을 의미한다.
  • ④ 식별자를 부여하기 위해 시스템적으로 강제 생성하는 일련번호와 같은 속성이다.
정답: ②
파생 속성(예: 이자, 총합계금액)은 계산을 통해 언제든 얻어낼 수 있지만, 매번 계산하면 성능이 저하되므로 미리 계산하여 저장해 두는 속성입니다. 원본 데이터가 변경될 때 파생 속성도 같이 업데이트해야 하므로(정합성 문제), **가급적 적게 정의**하는 것이 원칙입니다(①번 오답).
Q9. 정규화를 수행하지 않아 데이터의 중복이 발생할 때 나타날 수 있는 '이상 현상(Anomaly)'의 종류가 **아닌** 것은?
  • ① 삽입 이상 (Insertion Anomaly)
  • ② 삭제 이상 (Deletion Anomaly)
  • ③ 갱신 이상 (Update Anomaly)
  • ④ 검색 이상 (Search Anomaly)
정답: ④ 검색 이상
데이터 중복으로 인한 3대 이상 현상은 데이터를 집어넣을 때 불필요한 정보까지 넣어야 하는 **삽입 이상**, 특정 정보를 지울 때 필요한 정보까지 날아가는 **삭제 이상**, 중복된 데이터 중 일부만 수정되어 데이터가 꼬이는 **갱신 이상**입니다. 검색(조회) 이상은 존재하지 않습니다.
⭐️ 필수 기출
Q10. 데이터 모델링 시 '반정규화(Denormalization)'를 고려해야 하는 상황으로 **가장 부적절한** 것은?
  • ① 자주 사용되는 테이블에 접근하는 프로세스가 많고, 항상 일정한 범위만을 조회하여 조인이 빈번할 때
  • ② 테이블에 대량의 데이터가 있고, 이를 자주 집계(SUM, AVG 등)하여 성능 저하가 예상될 때
  • ③ 통계 정보를 자주 필요로 하여 별도의 요약/통계 테이블(Summary Table)을 생성하고자 할 때
  • ④ 데이터의 입력, 수정, 삭제가 매우 빈번하게 발생하여 데이터의 무결성을 엄격하게 보장해야 할 때
정답: ④
반정규화는 조회(SELECT) 성능을 올리는 대신, 입력/수정/삭제(INSERT, UPDATE, DELETE) 시 무결성이 깨질 위험을 감수하는 기법입니다. 데이터가 빈번하게 수정되고 무결성이 엄격히 요구되는 환경에서는 반정규화를 수행하면 치명적입니다.
Q11. IE(Information Engineering) 표기법에서, 'A 엔터티의 하나의 인스턴스에 대해 B 엔터티의 인스턴스가 1개 존재하거나, 아예 존재하지 않을 수 있음(선택적 1:1 관계)'을 의미하는 기호는?
  • ① 선 끝에 까마귀 발(<)과 수직선(|) 표시
  • ② 선 끝에 까마귀 발(<)과 동그라미(O) 표시
  • ③ 선 끝에 동그라미(O)와 수직선(|) 표시
  • ④ 이중 실선 표시
정답: ③ 선 끝에 동그라미(O)와 수직선(|) 표시
- 수직선( | ): 1개
- 동그라미( O ): 0개 (선택적)
- 까마귀 발( < ): 여러 개 (다수)
따라서 0개 또는 1개(선택적 1:1)는 **O와 |를 결합**하여 선 끝에 표기합니다.
Q12. 데이터 모델링에서 관계(Relationship)의 분류 중, 엔터티 간의 '행위(이벤트)'에 의해 파생되는 **'행위적 관계'**의 예시로 가장 적절한 것은?
  • ① 부서와 사원 (소속 관계)
  • ② 학교와 학생 (재학 관계)
  • ③ 고객과 상품 (주문 관계)
  • ④ 국가와 도시 (포함 관계)
정답: ③ 고객과 상품 (주문 관계)
소속, 재학, 포함과 같이 특정 상태로 존재하는 것은 '존재적 관계'입니다. 반면, '주문한다', '출석한다'와 같이 어떤 액션(이벤트)이 발생함으로써 생기는 동사적 관계는 **'행위적 관계'**입니다.
Q13. 주식별자(Primary Identifier)가 RDBMS 테이블의 기본키(Primary Key)로 생성될 때 시스템적으로 자동 보장되어야 하는 두 가지 데이터 무결성 제약조건은?
  • ① UNIQUE, CHECK
  • ② UNIQUE, NOT NULL
  • ③ FOREIGN KEY, DEFAULT
  • ④ NOT NULL, CHECK
정답: ② UNIQUE, NOT NULL
주식별자의 '유일성'은 UNIQUE 제약조건으로, '존재성(값이 반드시 있어야 함)'은 NOT NULL 제약조건으로 구현됩니다. PK 제약조건은 이 두 가지를 합친 것입니다.
Q14. 데이터 모델링의 3가지 관점 중, "업무가 실제로 하는 일은 무엇인지" 또는 "무엇을 어떻게(How) 처리해야 하는지"의 흐름을 모델링하는 관점은?
  • ① 데이터 관점(Data)
  • ② 프로세스 관점(Process)
  • ③ 상관 관점(Interaction)
  • ④ 구조 관점(Structure)
정답: ② 프로세스 관점
- **데이터 관점**: 명사형, 어떤 데이터가 있는지(What)
- **프로세스 관점**: 동사형, 업무가 어떻게 동작하는지(How)
- **상관 관점**: 프로세스가 데이터에 미치는 영향(CRUD)
Q15. 데이터 모델링 시 속성(Attribute)의 명칭을 부여하는 원칙으로 **가장 부적절한** 것은?
  • ① 해당 업무에서 실제로 사용하는 관용적인 현업 용어를 사용한다.
  • ② 타이핑의 편의를 위해 약어 사용을 극대화하여 속성명의 길이를 최대한 짧게 유지한다.
  • ③ 전체 데이터 모델에서 속성명은 가급적 유일성(Uniqueness)을 확보해야 한다.
  • ④ 복잡한 서술식보다는 의미가 뚜렷한 명사형으로 간결하게 작성한다.
정답: ②
속성명은 누구나 직관적으로 의미를 파악할 수 있어야 하므로, 뜻을 알기 힘든 지나친 약어 사용은 지양해야 합니다. 표준화된 약어만 제한적으로 사용해야 합니다.
⭐️ 함정 주의
Q16. 다음 SQL 문장의 수행 목적을 가장 올바르게 해석한 것은?
SELECT 담당자ID, COUNT(고객ID) FROM 영업담당 GROUP BY 담당자ID HAVING COUNT(고객ID) >= 10;
  • ① 담당자ID가 10번 이상인 영업담당자의 목록 조회
  • ② 배정된 고객이 10명 이상인 담당자ID와 그 담당자의 고객 수 조회
  • ③ 10명 이상의 담당자가 배정된 특정 고객들의 ID 목록 조회
  • ④ 전체 고객 수가 10명 이상일 때 모든 담당자의 고객 수 조회
정답: ②
GROUP BY 담당자ID로 묶었으므로 집계의 단위는 '각 담당자'입니다. HAVING COUNT(고객ID) >= 10은 그 그룹(담당자) 내에 속한 데이터(고객ID)의 개수가 10개 이상인 경우만 필터링하라는 뜻입니다.
⭐️ 필수 기출
Q17. 복합 주식별자를 구성하는 속성(예: 주문일자+주문번호+상품코드) 중 특정 속성(주문일자)을 제외해도 인스턴스를 유일하게 식별할 수 있는 상태라면, 이 주식별자는 식별자의 어떤 특성을 위배한 것인가?
  • ① 유일성 (Uniqueness)
  • ② 비가변성 (Invariability)
  • ③ 최소성 (Minimality)
  • ④ 존재성 (Existence)
정답: ③ 최소성
식별자는 인스턴스를 유일하게 식별하기 위해 **'꼭 필요한 최소한의 속성'**만으로 구성되어야 합니다(최소성). 빼도 식별이 가능하다는 것은 군더더기 속성이 포함되었다는 의미이므로 최소성 위배입니다.
Q18. 공통적인 속성을 가진 상위 엔터티를 도출하고, 고유한 개별 속성 및 관계를 가진 하위 엔터티들로 세분화하여 설계하는 논리적 데이터 모델링 기법은?
  • ① 정규화 (Normalization)
  • ② 반정규화 (Denormalization)
  • ③ 슈퍼타입/서브타입 (Super-type/Sub-type) 모델링
  • ④ 식별/비식별 관계 모델링
정답: ③ 슈퍼타입/서브타입 모델링
비슷한 엔터티들의 공통 부분(예: 사원)을 '슈퍼타입'으로 올리고, 직군별로 다른 속성(예: 정규직, 계약직)을 '서브타입'으로 내려 설계하는 기법입니다.
Q19. 다음 중 '논리적 데이터 모델링(Logical Data Modeling)' 단계에서 수행하는 핵심 작업으로 **가장 거리가 먼** 것은?
  • ① 모든 엔터티에 대한 식별자(PK) 확정
  • ② M:N (다대다) 관계를 1:M 관계로 해소 (교차 엔터티 도출)
  • ③ 데이터 중복을 제거하기 위한 정규화(Normalization) 수행
  • ④ 테이블의 저장 공간 할당 및 인덱스(Index) 설계
정답: ④
저장 공간 파티셔닝, 인덱스 설계, 특정 DBMS에 종속적인 데이터 타입 설정 등은 모두 실제 DB 구축 직전 단계인 **물리적 데이터 모델링**에서 수행하는 작업입니다.
Q20. 데이터 모델링에서 '도메인(Domain)'이 가장 직접적으로 무결성을 보장하는 방법은 무엇인가?
  • ① 부모 테이블에 없는 값이 자식 테이블의 외래키에 들어오는 것을 막아준다.
  • ② 기본키 값이 중복해서 입력되는 것을 차단한다.
  • ③ 속성에 지정된 타입이나 길이를 벗어난 값, 혹은 허용되지 않은 값(Check)의 입력을 차단한다.
  • ④ 릴레이션이 분해될 때 정보의 손실이 없도록 무손실 분해를 보장한다.
정답: ③
도메인은 속성이 가질 수 있는 값의 집합입니다. 도메인을 정의하면 해당 컬럼에 엉뚱한 타입의 데이터(예: 나이에 문자 입력)나 범위를 벗어난 값(예: 성별에 'Z' 입력)이 들어오는 것을 시스템적으로 차단(도메인 무결성)할 수 있습니다.
