🚀 2과목 도입: 트랜잭션(ACID)과 NULL

설계가 끝났다면 이제 데이터를 다룰 차례입니다.
데이터베이스가 데이터를 안전하게 지키는 원리와 가장 헷갈리는 미지의 값 NULL을 파헤칩니다.

1. 트랜잭션(Transaction)의 4대 특성 (ACID)

트랜잭션이란 '더 이상 쪼갤 수 없는 논리적 작업의 단위'입니다. 데이터베이스는 수강신청 과정 중 에러가 났을 때 데이터가 꼬이지 않도록 아래의 ACID 4가지 원칙을 무조건 지킵니다.

A
원자성 (Atomicity)
트랜잭션 내의 작업들은 모두 성공(Commit)하거나, 아예 모두 실패(Rollback)해야 합니다. (All or Nothing)
🎓 잔여 좌석 1개 감소 + 내 수강목록 추가는 무조건 동시에 이뤄져야 함. 하나만 성공하면 대형 사고!
C
일관성 (Consistency)
트랜잭션이 끝나도 데이터베이스의 규칙(무결성 제약조건)은 영원히 일관되게 유지되어야 합니다.
🎓 수강신청 전이나 후나 '최대 21학점 제한'이라는 학교 룰은 절대 깨지면 안 됨.
I
고립성 (Isolation)
하나의 트랜잭션이 실행 중일 때, 다른 트랜잭션이 중간에 끼어들어 데이터를 건드릴 수 없습니다.
🎓 남은 1자리를 두 명이 동시에 클릭했을 때, 서로 격리(Lock)시켜서 한 명만 등록되게 막아줌.
D
영속성 (Durability)
트랜잭션이 성공적으로 완료(Commit)되었다면, 그 결과는 서버가 고장 나도 영구적으로 보존되어야 합니다.
🎓 "신청 완료" 팝업을 본 직후 서버실에 불이 나도, 내 수강내역은 살아있어야 함.

2. 기출 0순위: NULL의 특성과 연산 (블랙홀 법칙)

NULL은 0(숫자)도 아니고, 공백(빈칸, '')도 아닙니다. '아직 정해지지 않은 미지의 값(Unknown)' 또는 '부재 값'입니다.

① NULL의 사칙 연산 = 블랙홀

어떤 숫자든 NULL과 사칙연산(+, -, *, /)을 하면 결과는 무조건 NULL로 오염됩니다.

성적: 30(중간) + NULL(기말결시) = NULL

② NULL의 비교 연산 = IS NULL

NULL은 미지의 값이므로 = 기호로 비교할 수 없습니다. 별도의 전용 연산자를 써야 합니다.

WHERE 성적 = NULL; (동작 안 함)
WHERE 성적 IS NULL; (정답)
WHERE 성적 IS NOT NULL; (NULL이 아닌 것 찾기)

🚨 특급 기출 함정: 집계함수와 NULL의 관계

SUM, AVG, MAX, MIN 같은 그룹 집계함수들은 NULL인 행(Row)을 아예 투명인간 취급(무시)하고 계산합니다.

  • 학생 3명의 점수가 [100점, 50점, NULL(결시)] 일 때:
  • SUM(점수) ➔ 150 (NULL은 무시됨)
  • AVG(점수) ➔ 150 / 2명 = 75점
    (※ 3명으로 나눠서 50점이 되는 것이 아님! NULL인 학생은 분모(N)에서도 쿨하게 제외됨!)

💡 유일한 예외: COUNT(*)

COUNT(컬럼명)은 NULL을 무시하지만, COUNT(*)는 테이블의 전체 '행(Row)의 개수'를 세기 때문에 NULL이 포함된 행도 숫자(1)로 카운트합니다!
