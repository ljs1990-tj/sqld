🎯 SQLD 1과목 벼락치기 요약 (1/2)

가장 기본이 되는 데이터 모델링의 기초부터
엔터티와 속성의 핵심 기출 포인트만 압축했습니다.

1. 데이터 모델링 기초 개념

① 3대 특징 (추·단·명)

  • 추상화: 현실을 일정한 형식에 맞춰 표현
  • 단순화: 누구나 이해하기 쉽게 제한된 표기법 사용
  • 명확화: 애매모호함 없이 의미를 정확히 기술

② 3대 관점

  • 데이터 관점: What (어떤 데이터가 얽혀있는가)
  • 프로세스 관점: How (어떤 일을 하는가)
  • 상관 관점: CRUD (데이터와 프로세스가 어떻게 상호작용하는가)

③ 3대 유의점 (죄악)

  • 중복: 같은 데이터가 여러 번 저장되는 것 방지
  • 비유연성: 사소한 업무 변화에 DB가 깨지는 것 방지
  • 비일관성: 데이터 간 모순이 발생하는 것 방지

2. 데이터 모델링 3단계 진행 순서 (기출 단골)

단계 특징 및 추상화 수준 핵심 수행 작업
1. 개념적 모델링 추상화 수준이 가장 높음
전사적(전체) 업무 관점		 핵심 엔터티 도출
초기 개괄적인 ERD 작성
2. 논리적 모델링 특정 DBMS(오라클 등)에 종속되지 않는 독립적 단계 정규화 수행 (가장 중요!)
식별자 확정, 관계 정의 완비
3. 물리적 모델링 추상화 수준이 가장 낮음 (가장 구체적)
특정 DBMS 성능/물리적 제약 고려		 테이블, 인덱스 생성
반정규화(성능 튜닝) 수행

3. 데이터 독립성과 3단계 스키마 (ANSI-SPARC)

데이터베이스 구조가 변해도 화면이나 프로그램이 깨지지 않도록 방어하는 3계층 구조입니다.

외부 스키마 (External)

사용자/개발자 관점
사용자마다 필요로 하는 화면이 다르므로 여러 개의 외부 스키마가 존재합니다.

개념 스키마 (Conceptual)

조직 전체 관점 (통합)
DB 전체를 아우르는 단 1개의 마스터 도면입니다. 데이터 모델링이 지향하는 스키마입니다.

내부 스키마 (Internal)

물리적 저장장치 관점
실제 하드디스크에 데이터가 어떻게 물리적으로 저장될 것인가를 정의합니다.

🚨 독립성 2가지 구분하기

논리적 독립성: 개념 스키마(통합 도면)가 변해도 외부 스키마(사용자 화면)는 영향받지 않음.
물리적 독립성: 내부 스키마(하드웨어)가 변해도 개념 스키마(통합 도면)는 영향받지 않음.

4. 엔터티(Entity)와 속성(Attribute) 기출 포인트

구분 시험에 무조건 나오는 핵심 O/X 규칙
엔터티의
5대 조건		 1. 유일한 식별자(PK)가 있어야 함.
2. 2개 이상의 인스턴스(데이터)와 2개 이상의 속성이 있어야 함.
3. 다른 엔터티와 반드시 1개 이상의 관계를 맺어야 함.
   (단, 공통코드/통계성 테이블은 관계 생략 가능 ➔ 단골 기출!)
엔터티의
발생 분류		 • 기본 엔터티: 부모 역할, 독립적 식별자 가짐 (예: 사원, 부서)
• 중심 엔터티: 기본에서 파생, 업무의 중심 (예: 접수, 주문)
• 행위 엔터티: 내용이 빈번하게 바뀌고 데이터 양이 가장 많음 (예: 주문내역, 출결이력)
속성의
성격 분류		 • 기본 속성: 원래 존재하는 데이터 (예: 이름, 가격)
• 설계 속성: 관리를 위해 억지로 만든 코드 (예: 사원번호, 상품코드)
• 파생 속성: 계산된 결과값. 무결성을 위해 최소화해야 함! (예: 총액, 평균)
도메인
(Domain)		 해당 속성이 가질 수 있는 값의 허용 범위 (데이터 타입, 크기, NOT NULL 여부, CHECK 제약조건 등)

🎯 1과목 기초 파트 필수 암기 공식

개 · 논 · 물 / 외 · 개 · 내
  • ✅ 모델링 3단계: [개]념적 ➔ [논]리적(정규화) ➔ [물]리적(성능)
  • ✅ 3단계 스키마: [외]부(사용자) ➔ [개]념(전체통합) ➔ [내]부(물리장치)
  • ✅ 4요소 개수 관계: 1개의 엔터티는 ➔ 2개 이상의 속성과 인스턴스를 가지며 ➔ 1개의 속성은 단 1개의 원자값(속성값)만 가진다.
