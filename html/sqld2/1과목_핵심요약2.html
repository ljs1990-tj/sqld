1. 관계 (Relationship)

① 관계의 2가지 분류

  • 존재에 의한 관계: 상태나 소속 자체 (예: 부서-사원)
  • 행위에 의한 관계: 특정한 행동/업무 (예: 고객-주문)

② 관계를 그리는 3요소

  • 관계명: 현재형 동사 사용 (예: 소속된다, 수강한다)
  • 관계차수: 1:1, 1:M, M:M (까마귀 발)
  • 관계선택사양: 필수참여(|), 선택참여(O)

🚨 다대다(M:M) 관계 기출 함정

M:M 관계는 개념적 모델링에서만 존재하며, 실제 물리적 DB로 만들 때는 [교차 엔터티(행위 엔터티)]를 추가하여 2개의 1:M 관계로 무조건 해소해야 합니다.

2. 식별자 (Identifier)

분류 핵심 요약
주식별자(PK)
4대 조건		 1. 유일성: 1명만 딱 찾아낼 수 있는가?
2. 최소성: 유일성을 만족하는 가장 적은 수의 속성인가?
3. 불변성: 한 번 정해지면 값이 절대 안 바뀌는가?
4. 존재성: 무조건 데이터가 있어야 하는가? (NOT NULL)
키(Key)의 종류 • 슈퍼키: 유일성만 만족 (거품 많음)
• 후보키: 유일성 + 최소성 만족 (PK 후보들)
• 기본키(PK): 최종 당선된 대표 키
• 대체키: 낙선한 후보키
• 외래키(FK): 다른 테이블에서 빌려온 연결 고리
식별자 관계 vs
비식별자 관계		 • 식별자 관계(실선): 부모 PK를 자식의 주식별자(PK)로 상속 ➔ SQL 쿼리 복잡해짐
• 비식별자 관계(점선): 부모 PK를 자식의 일반 속성(FK)으로만 상속 ➔ 과도한 JOIN 유발

3. 이상현상과 정규화 (Normalization)

정규화를 하지 않아 발생하는 3대 이상현상: 삽입 이상, 갱신 이상, 삭제 이상

① 제1정규형 (1NF)

"원자성 확보"
모든 속성은 단 하나의 값(원자값)만 가져야 함. (다중값 분리)

② 제2정규형 (2NF)

"부분 함수 종속성 제거"
PK가 2개 이상인 복합키일 때, PK 일부에만 얍삽하게 종속된 속성 분리.

③ 제3정규형 (3NF)

"이행 함수 종속성 제거"
일반 속성들끼리 꼬리를 무는(A➔B➔C) 구조 끊어내기.

④ BCNF

"결정자는 무조건 후보키"
일반 속성이 감히 기본키(PK)의 일부를 결정하는 하극상 분리.

4. 반정규화와 대용량 데이터 처리

구분 핵심 요약
반정규화 절차 1. 반정규화 대상 조사
2. 다른 방법 유도 검토 (뷰, 인덱스, 클러스터링 등)
3. 최후의 수단으로 반정규화 적용 (테이블, 속성, 관계)
슈퍼/서브 타입
변환 (물리 모델)		 • 1:1 타입: 개별 테이블로 모두 쪼갬 (조인 많음)
• Plus 타입: 슈퍼+서브 결합으로 테이블 2~3개 생성
• Single 타입: 조인이 귀찮아 통짜 테이블 1개로 뭉침 (NULL 많음)
파티셔닝
(Partitioning)		 • Range 파티션: 날짜나 숫자 등 연속적인 '범위' 기준
• List 파티션: 지점, 지역 등 명확한 특정 '값' 기준
• Hash 파티션: 관리자 통제 불가, '해시 알고리즘'으로 골고루 분산
