🚀 1과목 2장 심화: 반정규화와 대용량 데이터 처리

정규화로 예쁘게 쪼개둔 테이블이 실무의 거대한 트래픽을 만나면 조회(SELECT) 속도가 무너집니다.
데이터의 무결성을 조금 포기하더라도, 응답 속도(성능)를 끌어올리는 현실적인 스킬들을 배웁니다.

1. 반정규화 (De-normalization) : "조인(JOIN) 지옥 탈출"

정규화된 엔터티, 속성, 관계를 시스템 성능 향상과 개발/운영의 단순화를 위해 중복, 통합, 분리 등을 수행하는 데이터 모델링 기법입니다.

🎓 수강신청 비유: "학생 전체 평균 학점을 구해주세요!" 할 때마다 5개 테이블을 조인해서 계산하면 학교 서버가 뻗습니다. 차라리 [학생] 테이블에 '평균학점' 컬럼을 중복으로 하나 파서(반정규화) 점수가 바뀔 때마다 업데이트해두고, 조회할 땐 그 칸만 빠르게 읽는 전략입니다.

🚨 기출 출제 0순위: 반정규화 적용 3단계 절차

반정규화는 데이터의 정합성을 깨뜨릴 위험이 크므로 최후의 수단으로 써야 합니다. 무턱대고 합치는 것이 아니라 반드시 아래의 3단계 순서를 지켜야 하며, 시험에서 순서 맞추기 문제로 100% 출제됩니다.

① 반정규화 대상 조사

진짜로 데이터가 너무 많거나, 자주 엄청난 조인(JOIN)이 걸려서 성능이 심각하게 떨어지는지 조사합니다.

➔

② 다른 방법 유도 검토
(★가장 중요)

반정규화 대신 뷰(VIEW)를 만들거나, 인덱스(Index) 조정, 클러스터링, 어플리케이션(코드) 단의 로직 변경으로 해결할 수 없는지 먼저 검토합니다.

➔

③ 반정규화 적용

다른 방법으로도 답이 없을 때, 최후의 수단으로 테이블, 속성, 관계를 반정규화(중복 허용) 합니다.

2. 반정규화의 대표적인 기법들

무엇을 쪼개거나 합치느냐에 따라 크게 3가지로 나뉩니다.

  • 테이블 반정규화:
    • 테이블 병합: 1:1, 1:M, 슈퍼/서브 타입 테이블을 그냥 하나로 합쳐버림.
    • 테이블 분할: 테이블 1개가 덩치가 너무 크면, 수직(컬럼 기준) 또는 수평(로우 기준)으로 찢어버림.
  • 컬럼 반정규화 (가장 흔함):
    • 중복 컬럼 추가: 조인을 피하려고 A테이블에 있는 컬럼을 B테이블에도 똑같이 복사해 둠.
    • 파생 컬럼 추가: 미리 계산된 값(총합, 평균, 누적액)을 별도의 컬럼으로 만들어 둠.
    • 이력 테이블 컬럼 추가: 이력 데이터를 조회할 때 최근 값을 찾기 편하도록 '최근 변경일시' 같은 컬럼을 추가함.
  • 관계 반정규화: 중복된 관계(선)를 추가하여 조인 경로를 단축함. (테이블이나 컬럼과 달리 무결성이 깨지지 않는 장점이 있음)

3. 대용량 데이터 성능 1: 슈퍼/서브 타입 모델 변환

논리적 모델에서 공통 부분(슈퍼 타입)과 고유 부분(서브 타입)을 분리해 둔 것을, 실제 DB(물리 모델)에 구현할 때 데이터 양과 트랜잭션 성격에 따라 3가지 방법 중 하나를 선택합니다.

개별 테이블 (OneToOne)

1:1 타입 (OneToOne)

슈퍼 타입과 서브 타입을 각각 독립적인 1:1 테이블로 모두 쪼개서 만듭니다.

  • 장점: 테이블이 분리되어 있어 용량이 적고 구조가 명확함.
  • 단점: 정보를 볼 때마다 무조건 조인(JOIN)을 해야 해서 성능 저하 발생 가능.
슈퍼+서브 병합 (Plus)

플러스 타입 (Plus)

슈퍼 타입과 서브 타입을 결합(슈퍼+서브A, 슈퍼+서브B)하여 여러 개의 테이블로 만듭니다.

  • 장점: 조인이 감소하고 서브 타입별로 트랜잭션이 독립적일 때 아주 좋음.
  • 단점: 다른 서브 타입들끼리 합쳐서 봐야 할 때 쿼리(UNION ALL)가 복잡해짐.
통합 테이블 (Single)

싱글 타입 (Single)

조인이 귀찮으니 슈퍼와 서브 타입을 모두 뭉쳐서 하나의 거대한 통합 테이블로 만들어버립니다.

  • 장점: 조인이 아예 발생하지 않아 단순 조회 성능이 압도적임.
  • 단점: 데이터가 낭비되는 빈칸(NULL)이 뻥뻥 뚫리고, 테이블 덩치가 너무 커짐.

4. 대용량 데이터 성능 2: 파티셔닝 (Partitioning)

테이블 1개에 수천만 건 이상의 데이터가 쌓여 너무 뚱뚱해지면(Block I/O 폭발), 논리적으로는 1개의 테이블처럼 보이지만 물리적으로는 여러 파일로 쪼개서 저장하는 기술입니다.

  • ① Range 파티션
    (범위)
    가장 많이 쓰이는 방식입니다. 대상 테이블을 날짜나 숫자 값의 '연속적인 범위'를 기준으로 나눕니다.
    예: 2024년 데이터, 2025년 데이터, 2026년 데이터를 각각 다른 물리적 파일(파티션)에 분리 저장. (관리가 매우 편함)
  • ② List 파티션
    (특정 값)
    지점, 사업소, 지역 코드처럼 특정 명확한 '값(List)'을 기준으로 나눕니다.
    예: [서울] 파티션, [부산] 파티션, [인천] 파티션으로 분할. (단, 새로운 지역이 생기면 수동으로 추가해야 함)
  • ③ Hash 파티션
    (해시 함수)
    관리자가 범위를 지정할 수 없고, DBMS가 내부 해시 함수 알고리즘을 돌려서 알아서 골고루 데이터를 찢어(분산) 저장합니다.
    예: 특정 데이터가 어느 파티션에 들어갔는지 사람은 알기 힘들지만, 데이터가 한쪽으로 쏠리는 현상을 완벽하게 막아줍니다.

💡 파티셔닝의 가장 큰 장점

데이터 액세스 범위가 확 줄어들어(Full Scan 방지) 성능이 극대화되고, 데이터가 망가졌을 때 특정 파티션(예: 2023년 데이터 파일)만 독립적으로 백업/복구가 가능해집니다.
