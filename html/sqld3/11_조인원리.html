⚙️ 주제 11: 조인 수행 원리

JOIN을 명령했을 때 데이터베이스가 선택하는 3가지 조인 알고리즘.
실무 튜닝의 핵심이자 시험 단골 기출입니다.

1. NL Join (Nested Loop Join)

자바(Java) 등 프로그래밍 언어에서 사용하는 이중 for문(중첩 루프)과 작동 원리가 100% 동일합니다.

개발자 비유: 이중 for문
for (Student s : studentList) { // 선행 테이블 (Driving Table)
  for (Enrol e : enrolList) { // 후행 테이블 (Inner Table)
    if (s.stu_no == e.stu_no) { 결과 집합에 추가; }
  }
}
  • 동작 방식: 먼저 엑세스하는 테이블(Driving Table)에서 데이터를 한 건 읽고, 그 값을 들고 다음 테이블(Inner Table)을 뒤져서 조인합니다.
  • 가장 중요한 특징: 후행 테이블(Inner Table)의 조인 컬럼에 반드시 인덱스(Index)가 있어야 합니다. (인덱스가 없으면 매번 후행 테이블을 Full Scan 하므로 성능이 지옥으로 갑니다.)
  • 적합한 상황: 온라인 트랜잭션(OLTP) 환경에서 소량의 데이터를 좁은 범위로 조인할 때 가장 빠르고 훌륭합니다.

2. Sort Merge Join

인덱스가 없거나, 대량의 데이터를 조인해야 할 때 NL Join의 한계를 극복하기 위해 등장한 방식입니다. "각자 정렬부터 하고 만나자!"가 모토입니다.

개발자 비유: 정렬 후 병합
1. 학생 테이블을 '학번' 순서대로 정렬(Sort) 해둔다.
2. 수강 테이블도 '학번' 순서대로 정렬(Sort) 해둔다.
3. 양쪽 다 줄을 섰으니, 위에서부터 아래로 한 번만 훑으면서 스윽 병합(Merge) 한다!
  • 특징: 조인 키를 기준으로 양쪽 테이블을 모두 정렬(Sort)한 후 조인합니다. 인덱스가 없어도 가능합니다.
  • 장점: 동등(=) 조인뿐만 아니라, 크다/작다(>, <) 같은 Non-Equi Join(범위 조건)에서도 사용할 수 있습니다.
  • 치명적 단점: 데이터를 정렬(Sort)하는 데 CPU와 메모리(PGA) 자원을 무지막지하게 소모합니다. 데이터가 많으면 정렬하다가 시스템이 뻗을 수 있습니다.

3. Hash Join

현대 데이터베이스에서 대량의 데이터를 조인할 때 사용하는 가장 강력하고 진보된 방식입니다.

개발자 비유: 인메모리 HashMap
1. 둘 중 크기가 작은 테이블을 메모리에 통째로 올려 해시맵(HashMap)을 만든다. (Build 단계)
2. 큰 테이블을 읽으면서, 방금 만든 해시맵에 키(Key)를 던져서 매칭되는 값을 즉시 뽑아온다. (Probe 단계)
  • 특징: 정렬(Sort) 작업이 없어서 빠르고, 해시 함수 덕분에 인덱스가 없어도 빛의 속도로 조인합니다.
  • 적합한 상황: 데이터 웨어하우스(DW)나 대규모 통계/배치 작업 등 대용량 데이터를 묶을 때 최강의 성능을 냅니다.
  • 제약 조건 (기출 0순위): 해시 함수의 특성상 오직 동등 조인(=)에서만 사용 가능합니다! 크다/작다(>) 조건에서는 절대 해시맵을 쓸 수 없습니다.
