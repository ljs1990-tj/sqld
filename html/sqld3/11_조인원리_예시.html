🚨 실전 SQL 쿼리: 조인 실행 계획 분석

조건절(WHERE)과 데이터 크기에 따라 옵티마이저가
NL Join, Hash Join, Sort Merge Join을 어떻게 선택하는지 확인합니다.

1. 소량 데이터 검색 (NL Join 발동)

전체 데이터 중 딱 1명의 학생(옥한빛)의 수강 내역만 조회하는 상황입니다.

NESTED LOOPS
-- 옥한빛(1건) 데이터를 찾아 수강 테이블을 뒤지는 이중 for문
SELECT /*+ USE_NL(S E) */ S.stu_name, E.enr_grade
FROM student S JOIN enrol E
ON S.stu_no = E.stu_no
WHERE S.stu_no = '20153075'; -- PK로 단 1건만 특정!
Execution Plan
---------------------------------------------------
0 SELECT STATEMENT
1   NESTED LOOPS
2     TABLE ACCESS (BY INDEX ROWID) OF 'STUDENT' (Driving)
3       INDEX (UNIQUE SCAN) OF 'PK_STUDENT'
4     TABLE ACCESS (BY INDEX ROWID) OF 'ENROL' (Inner)
5       INDEX (RANGE SCAN) OF 'IDX_ENROL_STUNO'

➔ 분석: 찾을 데이터가 1건밖에 없으므로, 옵티마이저는 메모리에 해시맵을 띄우거나 정렬을 하는 수고를 하지 않습니다. 인덱스를 타고 빠르게 1건을 찾은 뒤(Driving), 수강 테이블의 인덱스(Inner)를 찔러보는 NL Join이 압도적으로 빠르기 때문입니다.

2. 대용량 동등 조인 (Hash Join 발동)

조건절이 없습니다. 전교생의 모든 수강 내역 통계를 뽑기 위해 대량의 테이블 두 개를 통째로 묶어야 합니다.

HASH JOIN
-- WHERE 조건 없이 전체 테이블 대 전체 테이블 조인!
SELECT /*+ USE_HASH(S E) */ S.stu_name, E.enr_grade
FROM student S JOIN enrol E
ON S.stu_no = E.stu_no; -- 동등(=) 조인
Execution Plan
---------------------------------------------------
0 SELECT STATEMENT
1   HASH JOIN
2     TABLE ACCESS (FULL) OF 'STUDENT' (Build)
3     TABLE ACCESS (FULL) OF 'ENROL' (Probe)

➔ 분석: 전체 데이터를 다 가져와야 하므로 인덱스(건건이 찔러보기)는 무의미해집니다. 옵티마이저는 테이블을 Full Scan해서 학생 테이블로 메모리에 Hash Map을 띄운(Build) 뒤, 수강 테이블을 읽으며 쫙쫙 매칭(Probe)해버립니다.

3. 범위(Non-Equi) 조인 (Sort Merge Join 발동)

현대 DB에서는 웬만하면 Hash Join이 이기지만, 해시맵을 만들 수 없는 크다/작다(>, <, BETWEEN) 조건이 들어오면 어쩔 수 없이 이 방식을 씁니다.

MERGE JOIN
-- 동등(=) 조건이 아닌 크기 비교(>) 조건 사용
SELECT /*+ USE_MERGE(S E) */ S.stu_name, E.enr_grade
FROM student S JOIN enrol E
ON S.stu_no > E.stu_no; -- 범위 조인 (Hash Join 사용 불가 조건!)
Execution Plan
---------------------------------------------------
0 SELECT STATEMENT
1   MERGE JOIN
2     SORT (JOIN)
3       TABLE ACCESS (FULL) OF 'STUDENT'
4     SORT (JOIN)
5       TABLE ACCESS (FULL) OF 'ENROL'

➔ 분석: 조인 조건이 = 가 아니기 때문에 Hash Join이 불가능합니다. 옵티마이저는 양쪽 테이블을 모두 메모리 공간(PGA)으로 가져와서 무겁게 정렬(SORT)을 먼저 수행한 후 병합(MERGE)을 시작합니다.
