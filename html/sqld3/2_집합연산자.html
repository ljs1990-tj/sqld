➕ SQLD 2과목 심화: 집합 연산자

JOIN이 테이블을 '가로'로 붙인다면, 집합 연산자는 테이블을 '세로'로 위아래로 이어 붙입니다.
수학 시간에 배웠던 합집합, 교집합, 차집합의 개념이 그대로 적용됩니다!

1. 4대 집합 연산자 (Set Operators)

두 개의 SELECT 문장 사이에 연산자를 끼워 넣어 결과 집합을 하나로 합칩니다.

A∪B
UNION
(합집합)
두 결과 집합을 하나로 합칩니다. 단, 중복된 데이터는 1건만 남기고 싹 다 지워버립니다. (이 과정에서 정렬 작업이 발생하여 속도가 느려집니다.)
A+B
UNION ALL
(단순 결합)
두 결과 집합을 중복을 제거하지 않고 있는 그대로 무식하게 위아래로 이어 붙입니다. 정렬 작업이 없어서 속도가 가장 빠릅니다.
A∩B
INTERSECT
(교집합)
두 결과 집합에서 공통으로 존재하는 데이터(양쪽에 다 있는 것)만 뽑아냅니다. (중복 데이터는 1건으로 처리)
A−B
MINUS
(차집합)
첫 번째 집합에서 두 번째 집합에 있는 데이터를 빼고, 순수하게 첫 번째 집합에만 남은 데이터를 뽑아냅니다.

🚨 기출 함정: MINUS와 EXCEPT

차집합을 구하는 연산자는 오라클(Oracle)에서는 MINUS를 사용하지만, SQL Server에서는 EXCEPT라는 키워드를 사용합니다. 시험에서 보기로 EXCEPT가 나오면 당황하지 마세요!

2. 기출 0순위: UNION vs UNION ALL

이 두 가지의 차이점을 묻는 문제는 매번 시험에 나옵니다. 실무에서도 성능(속도) 문제 때문에 가장 중요하게 다루는 부분입니다.

구분 UNION UNION ALL
중복 데이터 처리 중복을 제거하고 1건만 출력 중복 제거 없이 모두 그대로 출력
정렬(Sort) 여부 중복을 제거하기 위해 내부적으로 정렬(Sort) 발생 정렬 작업 아예 없음
실행 속도(성능) 매우 느림 🐢 매우 빠름 🚀 (권장)
-- 예시: 2025년 졸업생과 2026년 졸업생 합치기
SELECT 이름, 학과 FROM 졸업생_2025
UNION ALL   -- (성능을 위해 가급적 UNION ALL을 사용!)
SELECT 이름, 학과 FROM 졸업생_2026;

3. 집합 연산자를 사용할 때 지켜야 할 3가지 절대 규칙

위아래로 테이블을 이어 붙이려면 아귀가 맞아야 합니다. 다음 규칙 중 하나라도 어기면 SQL 에러가 발생합니다.

① 컬럼의 수가 똑같아야 한다!

위쪽 SELECT가 컬럼 3개를 뽑았으면, 아래쪽 SELECT도 무조건 컬럼 3개를 뽑아야 합니다.

② 컬럼의 데이터 타입이 호환되어야 한다!

위쪽의 1번 컬럼이 '숫자형'이면, 아래쪽의 1번 컬럼도 '숫자형'이어야 합니다. (위는 문자, 아래는 숫자면 에러 발생)

③ ORDER BY는 맨 마지막에 딱 1번만! (기출 함정)

각각의 SELECT 문장 안에는 ORDER BY(정렬)를 사용할 수 없습니다. 정렬은 덩어리들을 완전히 다 합쳐놓은 뒤, 맨 마지막에 딱 한 번만 작성할 수 있습니다.
(출력되는 컬럼의 이름(헤더)은 첫 번째 SELECT 문의 컬럼명을 따릅니다.)

🎯 실전 시험장 1초 컷 요약

  • ✅ UNION은 중복을 제거하느라 정렬(Sort)이 발생하여 느리다.
  • ✅ UNION ALL은 중복 제거 없이 위아래로 그냥 붙이므로 가장 빠르다.
  • ✅ 집합 연산자는 컬럼의 '개수'와 '데이터 타입'이 반드시 맞아야 한다.
  • ✅ ORDER BY는 두 SELECT문 사이에 올 수 없고, 쿼리 가장 마지막 줄에만 올 수 있다.
