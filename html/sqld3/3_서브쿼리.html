🕵️‍♂️ SQLD 2과목 심화: 서브쿼리 완벽 이해

쿼리(메인 쿼리) 안에 또 다른 쿼리(서브 쿼리)가 들어가는 구조입니다.
위치에 따른 명칭과, 반환되는 데이터의 '줄(행) 수'를 파악하는 것이 핵심입니다.

1. 서브쿼리는 어디에 쓰였는가? (위치별 명칭)

어느 절(Clause)에 들어갔느냐에 따라 부르는 이름이 완전히 다릅니다. 이 명칭을 묻는 문제가 단골로 출제됩니다.

① SELECT 절
➔ 스칼라 서브쿼리

마치 하나의 '컬럼(칸)'처럼 사용됩니다.

SELECT 이름,
  (SELECT AVG(학점) FROM 성적)
FROM 학생;

🚨 [주의] 무조건 단 1개의 행, 1개의 컬럼 값만 반환해야 합니다.

② FROM 절
➔ 인라인 뷰 (Inline View)

마치 하나의 '가상 테이블'처럼 사용됩니다.

SELECT A.이름
FROM (SELECT * FROM 학생 WHERE 학년=3) A;

💡 메모리에 임시로 만들어지는 테이블이며, ORDER BY를 쓸 수 있는 유일한 서브쿼리입니다.

③ WHERE / HAVING 절
➔ 중첩 서브쿼리

데이터를 필터링하는 '조건값'으로 사용됩니다.

SELECT 이름 FROM 학생
WHERE 학점 > (SELECT AVG(학점) FROM 학생);

💡 괄호 안의 결과가 1줄이냐 여러 줄이냐에 따라 쓸 수 있는 연산자가 달라집니다.

2. 기출 0순위: 단일행 vs 다중행 연산자

WHERE 절에 서브쿼리를 쓸 때, 서브쿼리의 결과가 여러 줄(다중행)로 나오면 `=` 기호로 비교할 수 없습니다. 반드시 다중행 전용 연산자를 써야 합니다.

연산자 의미 및 동작 원리
IN 서브쿼리가 뱉어낸 여러 개의 값 중 하나라도 똑같은 게 있으면 TRUE (OR 조건과 동일)
ANY (SOME) 비교 연산자(>, <, =)와 결합해서 씁니다. 여러 값 중 '아무거나 하나라도' 조건을 만족하면 TRUE
> ANY (10, 20, 30) : 최솟값인 10보다만 크면 됨.
< ANY (10, 20, 30) : 최댓값인 30보다만 작으면 됨.
ALL 비교 연산자와 결합. 여러 값을 '모두 다' 만족해야 TRUE
> ALL (10, 20, 30) : 가장 큰 값인 30보다도 더 커야 함.
< ALL (10, 20, 30) : 가장 작은 값인 10보다도 더 작아야 함.
EXISTS [기출 단골] 서브쿼리의 결과가 '존재하는지(1건이라도 있는지)' 자체만 확인합니다.
결과값이 무엇인지는 중요하지 않고, 데이터가 있으면 즉시 TRUE를 반환하고 검색을 멈춥니다.

🚨 치명적 에러 (시험 단골 오답)

SELECT * FROM 직원
WHERE 부서코드 = (SELECT 부서코드 FROM 부서 WHERE 위치='서울');

➔ 오류 발생! 서울에 있는 부서가 '영업부', '인사부' 2개가 나왔는데 그걸 = 기호 하나로 받을 수 없습니다. = 대신 IN을 써야 정상 작동합니다.

3. 메인 쿼리와의 관계 (연관 서브쿼리)

비연관 서브쿼리 (독립적)

서브쿼리가 메인 쿼리의 컬럼을 가지고 있지 않습니다. 서브쿼리가 혼자 먼저 1번 딱 실행되고, 그 결과를 메인 쿼리에 던져줍니다.

연관 서브쿼리 (Correlated Subquery)

서브쿼리 안에 메인 쿼리의 컬럼이 포함되어 있는 경우입니다.

  • 메인 쿼리가 먼저 데이터를 한 줄 읽고 ➔ 그 값을 서브쿼리에 던져서 실행 ➔ 다음 줄 읽고 또 서브쿼리 실행...
  • 메인 쿼리의 데이터(행) 건수만큼 서브쿼리가 반복 실행되므로 속도가 매우 느려집니다.

🎯 실전 시험장 1초 컷 절대 규칙

  • ✅ 서브쿼리는 반드시 괄호 () 로 감싸야 한다.
  • ✅ 서브쿼리는 기본적으로 ORDER BY를 쓸 수 없다. (단, 인라인 뷰 내부에서 TOP-N 쿼리를 할 때는 예외적으로 가능)
  • ✅ 다중행 결과가 나오는 서브쿼리에 =, >, < 같은 단일행 연산자를 쓰면 즉시 에러가 난다. (IN, ANY, ALL을 써야 함)
