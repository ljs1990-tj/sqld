🪟 SQLD 2과목 심화: 윈도우 함수

GROUP BY처럼 데이터를 하나로 뭉뚱그려버리지 않고!
데이터의 행(Row) 수를 그대로 유지하면서 순위, 비율, 누적합을 분석하는 마법입니다.

1. 윈도우 함수 기본 문법 (OVER 절)

윈도우 함수는 항상 OVER () 라는 전용 키워드와 함께 다닙니다. 이 괄호 안에서 그룹을 나누고 정렬을 수행합니다.

SELECT 이름, 부서명, 급여,
  RANK() OVER (
    PARTITION BY 부서명   -- 1. 부서별로 그룹을 나누고 (선택)
    ORDER BY 급여 DESC     -- 2. 급여가 높은 순으로 정렬해서 (필수)
  ) AS 부서내_급여순위
FROM 사원;

💡 PARTITION BY vs GROUP BY

GROUP BY를 쓰면 사원 100명의 데이터가 부서 개수인 4줄로 쪼그라들지만, PARTITION BY를 쓰면 사원 100명의 줄 수는 그대로 유지한 채 부서 내에서의 각 사원 순위만 계산해서 옆 칸에 띄워줍니다.

2. 기출 0순위: 순위 함수 3대장 비교

점수가 [100, 90, 90, 80]일 때, 동점자(90점)와 그다음 사람(80점)의 등수를 어떻게 매기는지에 따라 3가지로 나뉩니다. 이 셋의 출력 결과를 묻는 문제는 시험에 무조건 나옵니다!

① RANK

동점자는 같은 등수로 처리하고, 그다음 등수는 동점자 수만큼 건너뜁니다.

  • 100점 1등
  • 90점 2등
  • 90점 2등
  • 80점 4등

② DENSE_RANK

동점자는 같은 등수로 처리하지만, 그다음 등수를 건너뛰지 않고 빽빽하게(Dense) 채웁니다.

  • 100점 1등
  • 90점 2등
  • 90점 2등
  • 80점 3등

③ ROW_NUMBER

동점자고 뭐고 상관없이, 무조건 순서대로 고유한 일련번호를 부여합니다.

  • 100점 1
  • 90점 2
  • 90점 3
  • 80점 4

3. 행 순서 관련 함수 (LAG, LEAD)

SQL은 기본적으로 위아래 줄(행)끼리 값을 비교하는 것이 굉장히 어렵습니다. 이를 단번에 해결해 주는 오라클 전용 마법의 함수입니다.

함수명 작성법 기능
LAG (이전) LAG(컬럼, 칸수, 대체값) 내 위에 있는 이전 행(과거)의 값을 당겨옵니다.
예: LAG(매출, 1) ➔ 지난달 매출
LEAD (이후) LEAD(컬럼, 칸수, 대체값) 내 밑에 있는 다음 행(미래)의 값을 끌어올립니다.
예: LEAD(매출, 1) ➔ 다음 달 매출

💡 맨 처음과 맨 마지막: FIRST_VALUE, LAST_VALUE

파티션(그룹) 안에서 정렬된 결과 중 가장 첫 번째 값(1등)을 원하면 FIRST_VALUE, 가장 마지막 값(꼴등)을 원하면 LAST_VALUE를 사용합니다.

4. 그룹 내 비율 함수 (NTILE 주의!)

전체 합계 대비 내 값의 비율이나, 데이터를 N등분으로 쪼갤 때 사용합니다.

  • RATIO_TO_REPORT: 파티션 내 전체 SUM 값에 대한 현재 행 값의 백분율(0~1 사이)을 구합니다. (오라클 전용)
  • PERCENT_RANK: 맨 위(1등)를 0, 맨 아래(꼴등)를 1로 놓고 현재 행의 백분위 순위를 구합니다.
  • NTILE(N): 전체 데이터를 정확히 N개의 그룹(버킷)으로 공평하게 쪼개어 분배합니다. (매우 자주 출제됨!)
    예: 100명의 학생을 성적순으로 정렬 후 NTILE(4)를 적용하면, 25명씩 4그룹(1, 2, 3, 4)으로 나누어집니다.

🎯 실전 시험장 1초 컷 요약

  • ✅ RANK()는 공동 2등이 2명이면 그다음은 4등이다. (1, 2, 2, 4)
  • ✅ DENSE_RANK()는 공동 2등이 있어도 그다음은 무조건 3등이다. (1, 2, 2, 3)
  • ✅ ROW_NUMBER()는 동점자 따위 무시하고 1, 2, 3, 4 일련번호를 매긴다.
  • ✅ LAG은 위쪽(과거) 데이터, LEAD는 아래쪽(미래) 데이터를 당겨온다.
