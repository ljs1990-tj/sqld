🪟 실전 SQL 쿼리: 윈도우 함수 완벽 분석

ENROL 테이블의 수강 성적(enr_grade) 데이터를 활용하여
동점자가 발생했을 때 순위 함수 3대장이 어떻게 다르게 동작하는지 비교합니다.

1. RANK vs DENSE_RANK vs ROW_NUMBER

🎓 요구사항: ENROL 테이블에서 수강 성적(enr_grade)이 높은 순(DESC)으로 순위를 매겨 조회하시오.
단, 각기 다른 3가지 순위 함수를 모두 사용하여 차이를 비교하시오.

SELECT stu_no, sub_no, enr_grade,
  RANK() OVER(ORDER BY enr_grade DESC) AS rnk,
  DENSE_RANK() OVER(ORDER BY enr_grade DESC) AS dense_rnk,
  ROW_NUMBER() OVER(ORDER BY enr_grade DESC) AS row_num
FROM enrol;

💡 결과 완벽 해설

  • RANK: 65점 동점자가 2명 나오자 공동 6등으로 처리하고, 7등을 건너뛴 뒤 바로 8등으로 넘어갔습니다.
  • DENSE_RANK: 공동 6등 다음 순위를 건너뛰지 않고 7등으로 빽빽하게 채웠습니다.
  • ROW_NUMBER: 동점자든 뭐든 상관없이 그냥 데이터베이스가 읽은 순서대로 고유한 일련번호(6, 7)를 냅다 부여했습니다.

2. 그룹 안에서 순위 매기기 (PARTITION BY)

🎓 요구사항: STUDENT 테이블에서 '각 학과(stu_dept)별로' 키(stu_height)가 큰 순서대로 등수를 매기시오. (키가 NULL인 학생은 제외)

SELECT stu_dept, stu_name, stu_height,
  RANK() OVER(
    PARTITION BY stu_dept   -- 학과 단위로 파티션(벽)을 친다
    ORDER BY stu_height DESC
  ) AS dept_height_rnk
FROM student
WHERE stu_height IS NOT NULL;

🚨 기출 핵심 포인트

GROUP BY를 썼다면 기계과 1줄, 전기전자 1줄, 컴퓨터정보 1줄로 총 3줄로 데이터가 쪼그라들었을 것입니다. 하지만 윈도우 함수의 PARTITION BY는 원본 행(8줄)을 하나도 삭제하지 않고, 단지 순위를 계산할 때만 칸막이(벽) 역할을 하여 1등을 새롭게 초기화해 줍니다.
