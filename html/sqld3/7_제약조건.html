🏗️ SQLD 2과목 심화: DDL과 제약조건

테이블을 생성하고(CREATE), 수정하고(ALTER), 삭제하는(DROP) 명령어와
데이터 무결성을 지키는 제약조건(Constraints)의 핵심 기출 포인트를 파헤칩니다.

1. 테이블 생성과 5대 제약조건 (CREATE TABLE)

처음 제공해주신 ENROL(수강) 테이블의 쿼리를 자세히 뜯어보면, 데이터의 무결성(쓰레기 데이터가 들어오는 것을 방지)을 위한 제약조건(Constraints)이 숨어있습니다.

CREATE TABLE enrol (
  sub_no char(3) REFERENCES subject(sub_no), -- 외래키 (FK)
  stu_no char(8) REFERENCES student(stu_no), -- 외래키 (FK)
  enr_grade NUMBER
);
제약조건설명 및 기출 포인트
PRIMARY KEY (PK) 기본키. 하나의 테이블에서 각 행(Row)을 유일하게 식별합니다.
➔ 특징: UNIQUE(중복 불가) + NOT NULL(비어있을 수 없음) 속성을 동시에 가짐 (시험 단골!)
FOREIGN KEY (FK) 외래키. 다른 테이블의 PK나 UNIQUE 컬럼을 참조합니다. (위 코드의 REFERENCES)
➔ 수강 테이블(enrol)에 성적을 넣으려면, 반드시 학생 테이블(student)에 존재하는 학번(stu_no)이어야만 데이터 삽입이 가능합니다.
UNIQUE 고유키. 중복된 값을 허용하지 않습니다. (예: 주민번호, 이메일)
➔ 단, NULL 값은 허용하며, NULL은 여러 개 존재할 수 있습니다. (PK와의 결정적 차이)
NOT NULL 해당 컬럼에 NULL(빈칸) 값이 들어오는 것을 원천 차단합니다. 필수 입력값.
CHECK 입력될 수 있는 데이터의 조건을 구체적으로 제한합니다.
➔ 예: CHECK (enr_grade >= 0 AND enr_grade <= 100) 점수는 0~100점만 가능!

2. 기출 0순위: 외래키 연쇄 삭제 (CASCADE)

만약 자퇴를 해서 STUDENT 테이블에서 '옥한빛(20153075)' 학생의 데이터를 지우려(DELETE)고 하면 어떻게 될까요?

❌ 기본 상태: 무결성 제약조건 위배 에러 (ORA-02292)

현재 ENROL 테이블에는 옥한빛 학생의 수강 내역(102번, 105번 과목)이 남아있습니다. 자식 데이터(수강내역)가 부모 데이터(학생)를 참조하고 있기 때문에, DB는 부모 데이터의 삭제를 거부하며 에러를 발생시킵니다.

✅ 해결책: ON DELETE CASCADE / SET NULL

테이블을 생성할 때 참조 옵션을 달아주면 해결됩니다.

-- 1. CASCADE: 부모가 지워지면, 참조하던 자식 데이터(수강내역)도 함께 자동 삭제됨!
REFERENCES student(stu_no) ON DELETE CASCADE

-- 2. SET NULL: 부모가 지워지면, 자식 데이터의 학번 컬럼 값만 텅 빈 NULL로 변경됨!
REFERENCES student(stu_no) ON DELETE SET NULL

3. 구조 변경 (ALTER TABLE)

개발 도중 스키마(테이블 구조)를 변경해야 할 때 사용하는 명령어입니다. 시험에서는 Oracle과 SQL Server의 미묘한 문법 차이를 종종 출제합니다.

-- 1. 컬럼 추가 (ADD)
ALTER TABLE student ADD (stu_age NUMBER);

-- 2. 컬럼 삭제 (DROP COLUMN)
ALTER TABLE student DROP COLUMN stu_weight;

-- 3. 컬럼 수정 (데이터 타입이나 길이 변경)
-- [Oracle 기준: MODIFY 키워드 사용]
ALTER TABLE student MODIFY (stu_name varchar(20));
-- [SQL Server 기준: ALTER COLUMN 사용 (오답 보기로 자주 나옴!)]
-- ALTER TABLE student ALTER COLUMN stu_name varchar(20);

4. 심화 기출: 삭제 3대장 (DELETE vs TRUNCATE vs DROP)

데이터베이스의 데이터를 날려버리는 3가지 방식입니다. 이 셋의 차이점을 묻는 문제는 SQLD 객관식 단골 1번 손님입니다.

명령어 언어 종류 ROLLBACK (복구) 테이블 구조(껍데기) 특징 (로그 기록)
DELETE DML (조작어) 가능 (O) 유지됨 행(Row) 단위로 하나씩 지우며, 삭제 로그를 모두 남기기 때문에 가장 느림. 조건(WHERE) 지정 가능.
TRUNCATE DDL (정의어) 불가능 (X) 유지됨 조건(WHERE) 없이 테이블 안의 모든 데이터를 한 번에 밀어버림. 로그를 안 남겨서 속도가 매우 빠름.
DROP DDL (정의어) 불가능 (X) 삭제됨 (소멸) 테이블 안에 있는 데이터는 물론, 테이블 구조(껍데기) 자체를 DB에서 완전히 파괴해버림.

🚨 SQLD 필수 암기: Auto Commit의 저주

CREATE, ALTER, DROP, TRUNCATE와 같은 DDL 명령어는 실행 즉시 자동으로 COMMIT이 발생(Auto Commit)합니다.
즉, 개발자가 실수로 TRUNCATE TABLE student;를 쳤다면, ROLLBACK;을 외쳐도 이미 디스크에 영구 반영되어 데이터가 절대 돌아오지 않습니다!
