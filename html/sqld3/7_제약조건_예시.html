🚨 실전 SQL 쿼리: DDL과 제약조건 에러 분석

무결성을 지키기 위해 설정해 둔 PK, FK 제약조건이
잘못된 데이터 조작을 만났을 때 어떻게 비명을 지르는지 확인합니다.

1. PRIMARY KEY (기본키) 제약조건 위배

STUDENT 테이블의 stu_no는 기본키(PK)입니다. 중복 불가(UNIQUE) + 빈칸 불가(NOT NULL) 규칙이 강제됩니다.

❌ 상황 A: 기존 학번과 동일한 학번을 넣으려 할 때

-- 이미 존재하는 '옥한빛'의 학번(20153075)으로 신입생 추가 시도
INSERT INTO student (stu_no, stu_name, stu_dept)
VALUES ('20153075', '신입생', '기계');
ORA-00001: 무결성 제약 조건(SYS_C001234)에 위배됩니다.
(Unique constraint violated)

❌ 상황 B: 학번을 빈칸으로 넣으려 할 때

-- 학번(PK)에 NULL 값을 강제로 삽입 시도
INSERT INTO student (stu_no, stu_name)
VALUES (NULL, '유령학생');
ORA-01400: NULL을 (STUDENT.STU_NO) 안에 삽입할 수 없습니다.

2. FOREIGN KEY (외래키) 제약조건 위배

ENROL 테이블은 성적을 기록할 때, 반드시 STUDENT에 있는 학번과 SUBJECT에 있는 과목코드만 허용합니다.

❌ 상황: 없는 학생의 성적을 등록하려 할 때

-- 99999999 라는 학번은 STUDENT 테이블에 없음!
INSERT INTO enrol (sub_no, stu_no, enr_grade)
VALUES ('101', '99999999', 100);
ORA-02291: 무결성 제약조건이 위배되었습니다 - 부모 키가 없습니다.
(Parent key not found)

3. 부모 데이터 삭제 시 발생하는 일 (CASCADE)

STUDENT의 '옥한빛(20153075)' 학생이 자퇴를 해서 DB에서 지우려고 합니다. 그런데 옥한빛은 현재 ENROL 테이블에 수강 내역(102, 105 과목)이 남아있습니다.

⚠️ 참조 무결성 기본 작동 방식

DELETE FROM student WHERE stu_no = '20153075';
ORA-02292: 무결성 제약조건이 위배되었습니다 - 자식 레코드가 발견되었습니다.
(Child record found)

➔ 자식(수강내역)이 아직 부모(학생)를 가리키고 있어서, DB가 부모의 삭제를 막아버립니다. (고아 데이터를 만들지 않기 위함)

✅ 만약 테이블 생성 시 'ON DELETE CASCADE'를 주었다면?

애초에 테이블을 만들 때 ON DELETE CASCADE 옵션을 달아두었다면 결과는 완전히 달라집니다.

DELETE FROM student WHERE stu_no = '20153075';
1 행이 삭제되었습니다.
(시스템 백그라운드 메시지: ENROL 테이블에서 20153075 학생의 수강 내역 2건도 연쇄적으로 삭제되었습니다.)

4. 테이블 구조 변경 (ALTER TABLE)

학생 테이블(STUDENT)을 쓰다 보니, 이메일 주소를 받을 컬럼이 누락되어 뒤늦게 추가하고 이름의 길이 제한을 수정하는 실무 예시입니다.

-- 1. [컬럼 추가] 이메일 컬럼 추가
ALTER TABLE student ADD (stu_email varchar(50));

-- 2. [컬럼 수정] 학생 이름 길이를 12에서 20으로 늘림 (Oracle 표준)
ALTER TABLE student MODIFY (stu_name varchar(20));

-- 3. [컬럼 삭제] 사용하지 않는 체중(stu_weight) 컬럼 날리기
ALTER TABLE student DROP COLUMN stu_weight;

🚨 SQLD 기출 함정 포인트

컬럼을 수정할 때 오라클은 MODIFY를 쓰고, SQL Server는 ALTER COLUMN을 씁니다. 시험 문제에서 "다음 중 SQL Server에서 올바른 명령어는?" 이라고 물어보면 보기 중 ALTER COLUMN을 찾으셔야 합니다!
