📝 SQLD 2과목 심화: DML과 MERGE

실무에서 가장 많이 쓰는 데이터 입력(INSERT), 수정(UPDATE), 삭제(DELETE)와
시험 단골 손님인 'MERGE(병합)' 및 '트랜잭션(TCL)'의 핵심을 짚어봅니다.

1. 기본 DML (INSERT, UPDATE, DELETE)

너무 익숙한 내용이시겠지만, SQLD 시험에서 종종 묻는 오류 발생 케이스(제약조건 위배)를 중심으로 점검해 봅니다.

-- 1. INSERT (데이터 삽입)
INSERT INTO student (stu_no, stu_name, stu_dept)
VALUES ('20260001', '신입생', '컴퓨터정보');
-- ➔ 지정하지 않은 학년, 키, 성별 등은 자동으로 NULL로 채워집니다.

-- 2. UPDATE (데이터 수정)
UPDATE student
SET stu_weight = 70
WHERE stu_no = '20153075';

-- 3. DELETE (데이터 삭제)
DELETE FROM enrol
WHERE enr_grade < 60;

🚨 기출 단골: DML 실행 시 발생하는 에러 원인

  • INSERT 에러: student 테이블의 기본키(PK)인 stu_no를 빼먹고 INSERT 하거나, 이미 존재하는 학번을 또 넣으려고 할 때 (무결성 제약조건 위배).
  • UPDATE 대참사: WHERE 절을 빼먹고 UPDATE student SET stu_weight = 70;을 실행하면, 모든 학생의 몸무게가 70으로 바뀌어버림! (실무/시험 공통 대참사)

2. 기출 0순위: MERGE 문 (UPSERT)

실무에서 배치(Batch) 프로그램을 짤 때 구세주 같은 존재입니다. "데이터가 이미 있으면 UPDATE 하고, 없으면 새로 INSERT 해라!"라는 로직을 단 하나의 쿼리로 끝냅니다.

🎓 시나리오: 교무처에서 새로운 성적 엑셀 파일(가상 테이블: new_enrol_data)을 넘겨주었습니다. 이 데이터를 기존 enrol 테이블에 밀어 넣어야 합니다. (학번과 과목코드가 이미 존재하면 성적만 수정하고, 없으면 신규 수강 내역으로 추가)
MERGE INTO enrol E                    -- 타겟 테이블 (업데이트 될 곳)
USING new_enrol_data N              -- 소스 테이블 (새로 들어온 데이터)
ON (E.stu_no = N.stu_no AND E.sub_no = N.sub_no) -- 비교 조건(PK)

WHEN MATCHED THEN                   -- 데이터가 이미 존재한다면?
  UPDATE SET E.enr_grade = N.enr_grade

WHEN NOT MATCHED THEN               -- 데이터가 없다면?
  INSERT (sub_no, stu_no, enr_grade)
  VALUES (N.sub_no, N.stu_no, N.enr_grade);

💡 시험 문제 푸는 팁

객관식 보기로 "MERGE 문은 반드시 UPDATE와 INSERT가 모두 포함되어야 한다"라고 나오면 거짓(오답)입니다. 오라클에서는 필요에 따라 UPDATE 절만 쓰거나 INSERT 절만 단독으로 쓰는 것도 허용됩니다.

3. 트랜잭션 제어어(TCL)와 ACID 특성

DML(INSERT/UPDATE/DELETE)을 실행하면 데이터베이스는 즉시 디스크에 저장하지 않고 임시 메모리에만 올려둡니다. 이를 확정(COMMIT)하거나 취소(ROLLBACK)하는 것을 트랜잭션(Transaction) 제어라고 합니다.

[필수 암기] 트랜잭션의 4가지 특성 (ACID)

단답형 주관식이나 객관식 매칭 문제로 무조건 나오는 4총사입니다.

특성 (영문)의미 및 예시
원자성
(Atomicity)		 "All or Nothing"
은행 이체 시, '내 통장 출금'과 '상대 통장 입금'은 무조건 둘 다 성공하거나 둘 다 실패해야 합니다. 절반만 성공할 수 없습니다.
일관성
(Consistency)		 트랜잭션 실행 전후의 데이터베이스 상태는 항상 모순 없이 일관되어야 합니다.
(예: 잔고는 0원보다 작아질 수 없다는 제약조건을 항상 만족해야 함)
고립성
(Isolation)		 트랜잭션이 실행되는 도중에는 다른 트랜잭션이 끼어들어 데이터를 훔쳐보거나 방해할 수 없습니다.
지속성
(Durability)		 트랜잭션이 성공적으로 완료(COMMIT)되었다면, 서버 전원이 나가거나 장애가 발생하더라도 그 결과는 영구적으로 보존되어야 합니다.
