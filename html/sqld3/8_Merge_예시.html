🛠️ 실전 SQL 쿼리: DML과 MERGE

무심코 날린 UPDATE가 불러오는 대참사와
INSERT와 UPDATE를 한 번에 처리하는 MERGE 문의 마법을 확인합니다.

1. DML 실행 시 자주 만나는 에러 (무결성 위배)

개발자가 쿼리를 작성할 때 테이블 간의 관계(FK)를 고려하지 않으면 뱉어내는 대표적인 에러입니다.

❌ 1) 없는 과목을 수강 신청할 때 (FK 위배)

-- SUBJECT 테이블에 '999(낮잠자기)' 과목은 존재하지 않음!
INSERT INTO enrol (sub_no, stu_no, enr_grade)
VALUES ('999', '20153075', 100);
ORA-02291: 무결성 제약조건이 위배되었습니다 - 부모 키가 없습니다.
(부모 테이블인 SUBJECT에 해당 과목코드가 없어서 삽입 불가)

⚠️ 2) 실무 대참사: WHERE 절 없는 UPDATE

-- '옥한빛' 학생의 몸무게만 바꾸려다 WHERE 절을 빼먹음
UPDATE student
SET stu_weight = 70;
10 행이 업데이트되었습니다.
(전교생 10명의 몸무게가 전부 70kg으로 통일되어버림!)
-- 당황하지 말고 DML이므로 즉시 복구(TCL)를 외친다!
ROLLBACK;

➔ DML은 자동 커밋(Auto Commit)이 되지 않기 때문에, COMMIT을 하기 전이라면 언제든 ROLLBACK으로 살려낼 수 있습니다. (DDL과의 가장 큰 차이점)

2. MERGE 문의 마법 (UPSERT)

성적 처리 기간입니다. 교수님이 엑셀 파일(가상 테이블: NEW_DATA)로 성적표를 올렸습니다.
목표: 기존 수강 내역이 있으면 점수를 수정(UPDATE)하고, 수강 내역에 없던 과목이면 새로 추가(INSERT)하라!

기존 데이터 (ENROL)

학번과목점수
2013100110180
2013100110456

입력 데이터 (NEW_DATA)

학번과목점수
2013100110195
2013100110788
MERGE INTO enrol E -- 데이터가 최종 반영될 타겟
USING new_data N -- 입력받은 소스 데이터
ON (E.stu_no = N.stu_no AND E.sub_no = N.sub_no) -- 매칭 조건 (학번+과목)

WHEN MATCHED THEN -- (101번 과목은 이미 수강 내역에 존재함!)
  UPDATE SET E.enr_grade = N.enr_grade

WHEN NOT MATCHED THEN -- (107번 과목은 수강 내역에 없음!)
  INSERT (sub_no, stu_no, enr_grade)
  VALUES (N.sub_no, N.stu_no, N.enr_grade);
