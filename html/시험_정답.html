Q1. 발생 시점에 따른 엔터티 분류 중, 다음 설명에 해당하는 엔터티는 무엇인가?
업무 수행 과정에서 발생하며, 데이터량이 가장 많고 지속적으로 증가하는 엔터티이다. 두 개 이상의 부모 엔터티로부터 파생되는 경우가 많다. (예: 주문내역, 결제이력, 접속로그)
  • ① 기본 엔터티 (Fundamental Entity)
  • ② 중심 엔터티 (Main Entity)
  • ③ 행위 엔터티 (Action Entity)
  • ④ 개념 엔터티 (Conceptual Entity)
정답: ③ 행위 엔터티
발생량과 변동이 가장 많은 이벤트성 엔터티는 행위 엔터티(Action Entity)입니다.

Q2. 주식별자(Primary Identifier)가 가져야 할 4가지 핵심 특징 중, 다음 설명에 해당하는 것은?

  • ② 최소성 (Minimality)

Q4. 데이터 모델링의 다음 설계 기법을 무엇이라 하는가?
정규화를 수행하여 데이터 무결성을 확보한 이후, 조인(JOIN)으로 인한 조회(SELECT) 성능 저하를 방지하기 위해 의도적으로 테이블을 병합, 분할하거나 데이터를 중복시키는 성능 향상 기법이다.
정답: 반정규화 (또는 비정규화, Denormalization)
조회 성능을 위해 무결성을 일부 포기하고 중복을 허용하는 물리적 설계 기법입니다.

  • ① 기본 속성은 업무 도메인에서 원래부터 추출된 본질적인 속성을 의미한다.
  • ② 설계 속성은 원래 업무에는 없지만 시스템 관리를 위해 설계자가 인위적으로 부여한 속성이다.
  • ③ 파생 속성은 다른 속성의 영향을 받아 계산되거나 유도되는 속성이다.
  • ④ 파생 속성은 데이터 조회 시 계산을 최소화하므로 가급적 많이 정의하는 것이 무결성 유지에 유리하다.
정답: ④
파생 속성은 미리 계산해 두기 때문에 조회(SELECT) 성능은 좋아질 수 있지만, 원본 데이터가 변경될 때마다 갱신해야 하므로 무결성(정합성) 유지가 까다롭습니다. 따라서 가급적 적게 정의해야 합니다.

Q8. 그룹 함수(Aggregate Function)와 NULL 값의 처리에 대한 설명으로 가장 옳지 않은 것은?
  • ① SUM(컬럼)은 데이터 중 NULL 값을 제외하고 합계를 계산한다.
  • ② COUNT(*)는 NULL 값을 포함한 테이블의 전체 행(Row) 수를 반환한다.
  • ③ AVG(컬럼)은 연산 시 NULL 값을 0으로 간주하여 전체 건수에 포함해 평균을 계산한다.
  • ④ MAX(컬럼)은 NULL 값을 무시하고 존재하는 값 중 최댓값을 구한다.
정답: ③
AVG 함수는 NULL을 0으로 취급하지 않고 아예 모수(분모)에서 제외하고 평균을 냅니다. NULL을 0으로 계산하고 싶다면 AVG(NVL(컬럼, 0))을 사용해야 합니다.

  • ② CROSS JOIN
  • ③ OUTER JOIN

INNER JOIN은 교집합만, OUTER JOIN은 기준 테이블의 남는 데이터까지 모두 가져오는 방식입니다.

Q10. 다음 설명에 해당하는 명령어를 적으시오.
테이블의 구조는 남겨두고 전체 데이터를 삭제하는 명령어이다. DML인 DELETE와 달리 DDL에 해당하여 롤백(ROLLBACK)이 불가능하며, 저장 공간을 즉시 반환하여 처리 속도가 매우 빠르다.
정답: TRUNCATE (또는 TRUNCATE TABLE)
- DELETE: DML, 롤백 가능, 공간 유지
- TRUNCATE: DDL, 롤백 불가, 공간 반환
- DROP: 아예 테이블 구조까지 삭제

Q11. 다음 설명이 가리키는 조인 방식은 무엇인가?
두 테이블 간에 논리적인 조인 조건(WHERE 절이나 ON 절 등)이 없을 때, 두 테이블의 모든 행이 각각 한 번씩 조합되어 만들어지는 조인이다. 결과 행의 수는 두 테이블 행의 곱이 된다.
정답: CROSS JOIN (또는 카테시안 곱, Cartesian Product)
N행 테이블과 M행 테이블이 조인 조건 없이 만날 때 N*M행이 만들어지는 조인입니다.

Q12. 오라클(Oracle) 함수 중, 입력된 두 개의 인자 값이 같으면 NULL을 반환하고, 다르면 첫 번째 인자 값을 반환하는 함수는 무엇인가?
정답: NULLIF
NULLIF(A, B) : A와 B가 같으면 NULL을, 다르면 A를 반환하는 함수입니다.

Q13. 다음 중 데이터 조작어(DML)인 INSERT, UPDATE, DELETE 문에 대한 설명으로 가장 옳지 않은 것은?
  • ① 테이블에 새로운 데이터를 입력하거나, 기존 데이터를 수정 및 삭제하는 명령어이다.
  • ② DML 명령어를 실행하면 DDL과 마찬가지로 즉시 데이터베이스에 반영(Auto Commit)되므로 ROLLBACK을 통해 취소할 수 없다.
  • ③ UPDATE와 DELETE 문에서 WHERE 절을 생략하면 테이블에 있는 모든 행의 데이터가 수정되거나 삭제된다.
  • ④ INSERT 문에서 데이터를 입력할 때, 테이블의 모든 컬럼에 값을 입력하는 경우 컬럼명 리스트를 생략할 수 있다.
정답: ②
오라클 기준으로 DML(INSERT, UPDATE, DELETE)은 실행 후 COMMIT을 해야 완전 반영되며, ROLLBACK을 통해 언제든지 취소(복구)할 수 있습니다. (단, DDL은 롤백 불가)
2과목
Q14. [직원] 테이블에서 부서코드가 'D10'인 직원들의 급여(SALARY)를 5000으로 수정하고자 한다. 다음 중 가장 올바른 SQL 문장은?
  • ① ALTER TABLE 직원 SET SALARY = 5000 WHERE 부서코드 = 'D10';
  • ② MODIFY 직원 SET SALARY = 5000 WHERE 부서코드 = 'D10';
  • ③ UPDATE FROM 직원 SET SALARY = 5000 WHERE 부서코드 = 'D10';
  • ④ UPDATE 직원 SET SALARY = 5000 WHERE 부서코드 = 'D10';
정답: ④
데이터 수정 명령어는 UPDATE이며, 문법은 UPDATE 테이블명 SET 컬럼명=값 WHERE 조건; 입니다. ALTER나 MODIFY는 테이블의 '구조'를 변경할 때 씁니다.

Q16. DML인 DELETE FROM 테이블명;과 DDL인 TRUNCATE TABLE 테이블명;은 모두 데이터를 지우는 역할을 한다. 두 명령어 중 실행 후 트랜잭션을 취소(ROLLBACK)하는 것이 불가능하여 즉시 영구 삭제되는 명령어는 무엇인가?
정답: TRUNCATE (또는 TRUNCATE TABLE)
DELETE는 로그를 남기며 지워 롤백이 가능하지만, TRUNCATE는 DDL이므로 롤백이 불가능합니다.

Q17. 두 테이블을 결합하는 조인(JOIN)에 대한 설명으로 가장 옳지 않은 것은?
  • ① INNER JOIN(내부 조인)은 두 테이블 간에 조인 조건을 만족하는 데이터(교집합)만 추출한다.
  • ② CROSS JOIN(교차 조인)은 조인 조건이 없을 때 수행되며 결과는 두 테이블 행의 곱이 된다.
  • ③ LEFT OUTER JOIN(왼쪽 외부 조인)은 기준이 되는 왼쪽 테이블의 데이터가 조건에 안 맞아도 모두 출력된다.
  • ④ NATURAL JOIN(자연 조인)은 두 테이블에서 이름이 같은 컬럼들을 기준으로 자동으로 OUTER JOIN을 수행한다.
정답: ④
NATURAL JOIN은 두 테이블에서 이름과 데이터 타입이 같은 컬럼을 찾아 자동으로 EQUI JOIN (INNER JOIN, 내부 조인)을 수행합니다. OUTER JOIN을 수행한다는 설명은 틀렸습니다.
2과목
Q18. 데이터 집계를 위한 그룹 함수(Aggregate Function)와 GROUP BY 절에 대한 설명으로 가장 옳지 않은 것은?
  • ① GROUP BY에 명시되지 않은 일반 컬럼은 SELECT 절에서 그룹 함수와 함께 단독으로 조회할 수 없다.
  • ② WHERE 절은 데이터를 그룹화하기 전에 먼저 필터링을 수행하므로, WHERE 절 안에서는 그룹 함수를 조건으로 쓸 수 없다.
  • ③ HAVING 절은 GROUP BY 절보다 먼저 수행되어 그룹화할 데이터를 미리 필터링하는 역할을 한다.
  • ④ COUNT(*)를 제외한 대부분의 그룹 함수는 해당 컬럼의 NULL 값을 무시하고 연산을 수행한다.
정답: ③
HAVING 절은 데이터를 GROUP BY로 그룹화한 '이후'에 그룹 단위의 조건을 필터링하는 역할을 합니다. (논리적 수행 순서: WHERE ➔ GROUP BY ➔ HAVING)

Q19. 두 테이블을 조인할 때, 조인 조건이 동등(=) 조건이 아닌 크거나 작거나(BETWEEN, >, < 등) 하는 연산자를 사용하여 조인을 수행하는 방식을 무엇이라 하는가?
정답: 비등가 조인 (Non-Equi Join)
정확히 일치(=)하는 값으로 연결되는 것을 등가 조인(Equi Join), 사이 값이나 대소 비교 연산자로 연결되는 것을 비등가 조인(Non-Equi Join)이라고 합니다.

Q20. [직원] 테이블의 전체 직원은 총 10명이다. 이 중 '보너스' 컬럼에 값이 입력된 직원은 7명이고, 나머지 3명은 값이 없는 상태(NULL)이다. 이때 SELECT COUNT(보너스) FROM 직원; 을 실행했을 때 반환되는 결과값은 얼마인가?
정답: 7
COUNT(*)는 NULL을 포함해 전체 행의 수(10)를 세지만, COUNT(컬럼명)은 NULL 값을 제외한 실제 데이터의 수만 계산합니다.
