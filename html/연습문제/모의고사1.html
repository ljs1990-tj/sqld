Q01. 데이터 모델링의 3단계 중, 식별자를 확정하고 정규화를 수행하며 M:N 관계를 해소하는 가장 핵심적인 단계는?
  • ① 개념적 데이터 모델링
  • ② 논리적 데이터 모델링
  • ③ 물리적 데이터 모델링
  • ④ 추상적 데이터 모델링
상세 해설
정답은 ② 논리적 데이터 모델링입니다.
  • ① 개념적 데이터 모델링: 핵심 엔터티를 도출하고 ERD를 창출하는, 추상화 수준이 가장 높은 초기 단계입니다.
  • ② 논리적 데이터 모델링: 식별자 확정, 정규화 수행, M:N 관계 해소 등 데이터베이스 설계의 가장 핵심적인 작업이 이루어집니다. (특정 DBMS 종속 X)
  • ③ 물리적 데이터 모델링: 특정 DBMS의 디스크 저장 구조, 성능, 인덱스 등을 고려하여 물리적인 스키마를 생성하는 마지막 단계입니다.
  • ④ 추상적 데이터 모델링: 존재하지 않는 용어입니다.
Q02. 엔터티(Entity)의 특징으로 가장 거리가 먼 것은?
  • ① 업무에서 필요로 하고 관리하고자 하는 정보다.
  • ② 유일한 식별자에 의해 식별이 가능해야 한다.
  • ③ 엔터티는 단 1개의 속성만 가져도 무방하다.
  • ④ 반드시 두 개 이상의 인스턴스 집합이어야 한다.
상세 해설
정답은 ③입니다.
  • ①, ②, ④: 모두 엔터티가 반드시 갖춰야 할 올바른 특징입니다.
  • ③ 엔터티는 단 1개의 속성만 가져도 무방하다 (X): 엔터티는 유일한 식별자 속성과 더불어 일반 속성 등 반드시 2개 이상의 속성(Attribute)을 가져야 합니다.
Q03. 속성의 특성에 따른 분류 중, '총 금액', '평균 점수'와 같이 다른 속성들의 영향을 받아 계산되어 도출되는 속성은?
  • ① 기본 속성
  • ② 설계 속성
  • ③ 파생 속성
  • ④ 시스템 속성
상세 해설
정답은 ③ 파생 속성입니다.
  • ① 기본 속성: 이름, 나이처럼 업무 분석을 통해 처음부터 정의된 가장 일반적인 속성입니다.
  • ② 설계 속성: 업무에는 없었지만 설계를 하면서 코드, 일련번호처럼 인위적으로 만들어낸 속성입니다.
  • ③ 파생 속성: 다른 속성의 값을 이용하여 계산되거나 유도된(Derived) 속성입니다.
  • ④ 시스템 속성: 속성의 3가지 분류(기본/설계/파생)에 해당하지 않는 가짜 선지입니다.
Q04. 주식별자(Primary Identifier)가 가져야 할 4가지 특성 중, "주식별자를 구성하는 속성의 수는 유일성을 만족하는 최소의 수가 되어야 한다"는 성질은?
  • ① 유일성
  • ② 최소성
  • ③ 존재성
  • ④ 불변성
상세 해설
정답은 ② 최소성입니다.
  • ① 유일성: 주식별자에 의해 모든 인스턴스(행)가 유일하게 구분되어야 함을 의미합니다.
  • ② 최소성: 식별자를 구성하는 속성의 개수가 가장 적어야 한다는 의미입니다.
  • ③ 존재성: 주식별자는 값이 반드시 존재해야 함(NOT NULL)을 의미합니다.
  • ④ 불변성: 주식별자의 값은 한 번 지정되면 자주 변하지 않아야 함을 의미합니다.
Q05. 부모 엔터티로부터 상속받은 식별자를 자식 엔터티의 주식별자(PK)로 사용하지 않고, 일반 속성(외래키)으로만 사용하는 관계는?
  • ① 1:1 관계
  • ② 재귀적 관계
  • ③ 식별자 관계 (Identifying)
  • ④ 비식별자 관계 (Non-Identifying)
상세 해설
정답은 ④ 비식별자 관계입니다.
  • ① 1:1 관계: 관계의 차수(수량)를 나타내는 용어입니다.
  • ② 재귀적 관계: 자기 자신 엔터티 내부에서 맺어지는 관계입니다.
  • ③ 식별자 관계 (실선): 부모의 주식별자를 자식이 상속받아 자신의 '주식별자(PK)'의 일부로 포함하는 강한 연결 관계입니다.
  • ④ 비식별자 관계 (점선): 부모의 식별자를 일반 속성(단순 FK)으로만 받아 사용하는 약한 연결 관계입니다.
Q06. 데이터 정규화 과정에서 주식별자가 복합키일 때 발생하는 '부분 함수 종속성'을 제거하는 단계는?
  • ① 제1정규형 (1NF)
  • ② 제2정규형 (2NF)
  • ③ 제3정규형 (3NF)
  • ④ BCNF
상세 해설
정답은 ② 제2정규형입니다.
  • ① 제1정규형: 모든 속성은 다중값이 아닌 '원자성(단일 값)'을 가져야 합니다.
  • ② 제2정규형: 주식별자가 2개 이상의 복합키일 때, 일부 식별자에만 종속되는 '부분 함수 종속성'을 제거합니다.
  • ③ 제3정규형: 주식별자가 아닌 일반 속성들 간에 존재하는 '이행 함수 종속성'을 분리합니다.
  • ④ BCNF: 결정자이면서 후보키가 아닌 것들을 제거하는 강력한 정규형입니다.
Q07. 다음 중 '이행 함수 종속성 (A ➔ B 이고 B ➔ C 일 때, A ➔ C 가 성립)'을 제거하여 일반 속성 간의 종속을 없애는 정규화 단계는?
  • ① 제1정규형
  • ② 제2정규형
  • ③ 제3정규형
  • ④ 제4정규형
상세 해설
정답은 ③ 제3정규형입니다.
  • 일반 속성(B)이 다른 일반 속성(C)을 결정짓는 이행 함수 종속(Transitive Dependency)을 쪼개어 별도의 테이블로 분리하는 것은 제3정규형(3NF)의 핵심 작업입니다.
Q08. 반정규화(Denormalization)를 수행하는 가장 주된 목적은 무엇인가?
  • ① 시스템의 데이터 조회 성능을 향상시키기 위해
  • ② 데이터의 중복을 완벽히 제거하기 위해
  • ③ 데이터 무결성을 더욱 강력하게 보장하기 위해
  • ④ 논리적 데이터 모델링을 단순화하기 위해
상세 해설
정답은 ① 조회 성능 향상입니다.
  • ①: 과도한 정규화로 인해 테이블 조인(Join)이 많아져 조회가 느려지는 것을 막기 위해, 데이터 중복을 허용하더라도 테이블을 다시 합치는 것이 반정규화입니다.
  • ②, ③: 반정규화는 오히려 데이터 중복을 '허용'하므로 갱신 이상이 발생할 수 있어 데이터 무결성은 '저하'될 위험이 있습니다.
  • ④: 반정규화는 논리 단계가 아닌 주로 '물리적 데이터 모델링' 성능 최적화 관점에서 이루어집니다.
Q09. 데이터 독립성을 보장하기 위한 3단계 스키마 구조 중, 데이터가 물리적인 디스크에 어떻게 저장되는지를 정의하는 스키마는?
  • ① 외부 스키마
  • ② 개념 스키마
  • ③ 내부 스키마
  • ④ 논리 스키마
상세 해설
정답은 ③ 내부 스키마입니다.
  • ① 외부 스키마: 개별 사용자나 응용 프로그램이 바라보는 관점(View)입니다.
  • ② 개념 스키마: 모든 사용자의 관점을 통합한 전체 데이터베이스의 논리적 구조(뼈대)입니다.
  • ③ 내부 스키마: 실제 하드디스크에 데이터가 어떻게 저장되는지 물리적 저장 구조를 정의합니다.
  • ④ 논리 스키마: 3단계 스키마 구조 명칭에 존재하지 않습니다.
Q10. 각 속성(Attribute)이 가질 수 있는 값의 범위(데이터 타입, 크기, 제약조건 등)를 의미하는 용어는?
  • ① 튜플 (Tuple)
  • ② 도메인 (Domain)
  • ③ 인스턴스 (Instance)
  • ④ 릴레이션 (Relation)
상세 해설
정답은 ② 도메인입니다.
  • ① 튜플: 릴레이션(테이블)을 구성하는 행(Row)입니다.
  • ② 도메인: 특정 속성이 가질 수 있는 유효한 값의 집합(예: 성별은 'M', 'F'만 가능)을 의미합니다.
  • ③ 인스턴스: 엔터티에 실제로 저장되는 구체적인 데이터 행(Row)을 의미합니다.
  • ④ 릴레이션: 관계형 데이터베이스에서 데이터를 저장하는 2차원 표(테이블)입니다.
💻 제 2과목 : SQL 기본 및 활용 (20문제)
Q11. 다음 데이터 삭제 명령어 중 시스템 로그를 남기며 ROLLBACK을 통해 데이터를 복구할 수 있는 명령어는?
  • ① DELETE
  • ② TRUNCATE
  • ③ DROP
  • ④ REMOVE
상세 해설
정답은 ① DELETE입니다.
  • ① DELETE: DML(데이터 조작어)이므로 트랜잭션의 대상이 되어 처리 후 ROLLBACK이 가능합니다.
  • ② TRUNCATE: 데이터만 삭제하지만 DDL이므로 자동으로 Commit 처리되어 복구가 불가능합니다.
  • ③ DROP: DDL이므로 데이터와 테이블 구조 자체를 파괴하며 복구가 불가능합니다.
  • ④ REMOVE: 표준 SQL의 데이터 삭제 명령어가 아닙니다.
Q12. 긴 트랜잭션 수행 중 문제가 발생했을 때 전체를 취소하지 않고 특정 지점까지만 ROLLBACK 하기 위해 지정하는 TCL 명령어는?
  • ① COMMIT
  • ② CHECKPOINT
  • ③ SAVEPOINT
  • ④ ROLLBACK TO START
상세 해설
정답은 ③ SAVEPOINT입니다.
  • ① COMMIT: 트랜잭션의 작업 결과를 DB에 영구적으로 반영합니다.
  • ② CHECKPOINT: 메모리 버퍼의 변경 사항을 디스크에 물리적으로 기록하는 시스템 동작입니다.
  • ③ SAVEPOINT: 긴 트랜잭션 내에 중간 저장 지점을 만들어, 에러 시 ROLLBACK TO 세이브포인트명으로 일부만 취소할 수 있게 합니다.
Q13. SELECT 10 + NULL FROM DUAL; 쿼리의 실행 결과로 올바른 것은?
  • ① 10
  • ② 0
  • ③ 에러 발생
  • ④ NULL
상세 해설
정답은 ④ NULL입니다.
  • 관계형 DB에서 숫자 연산(+, -, *, /)에 NULL이 하나라도 포함되면 그 결과는 무조건 NULL이 됩니다. (알 수 없는 값과 연산하면 결과도 알 수 없음)
Q14. 오라클의 NVL2(expr1, expr2, expr3) 함수에 대한 설명으로 올바른 것은?
  • ① expr1이 NULL이면 expr2를 반환한다.
  • ② expr1이 NULL이 아니면 expr2를 반환하고, NULL이면 expr3을 반환한다.
  • ③ expr1과 expr2가 같으면 NULL을 반환한다.
  • ④ 세 개의 인자 중 최초로 NULL이 아닌 값을 반환한다.
상세 해설
정답은 ②입니다.
  • ①은 NVL(expr1, expr2) 함수에 대한 설명입니다.
  • ②는 NVL2 함수에 대한 설명입니다. (값이 있을 때와 없을 때를 동시에 분기 처리)
  • ③은 NULLIF(expr1, expr2) 함수에 대한 설명입니다.
  • ④는 COALESCE(expr1, expr2, expr3) 함수에 대한 설명입니다.
Q15. GROUP BY 절을 통해 그룹화된 데이터들에 대해 필터링 조건을 부여할 때 사용하는 SQL 절은?
  • ① WHERE
  • ② ORDER BY
  • ③ HAVING
  • ④ PARTITION BY
상세 해설
정답은 ③ HAVING입니다.
  • ① WHERE: GROUP BY로 묶기 전의 개별 기초 데이터를 필터링합니다.
  • ③ HAVING: GROUP BY로 묶인 후의 그룹(집계 결과)에 조건을 부여합니다. (예: HAVING SUM(급여) > 5000)
  • ④ PARTITION BY: 윈도우 함수 내부에서 그룹을 나눌 때 사용하는 구문입니다.
Q16. SQL의 논리적 수행 순서를 고려할 때, SELECT 절에서 정의한 별칭(Alias)을 절대 사용할 수 없는 절은?
  • ① ORDER BY 절
  • ② WHERE 절
  • ③ HAVING 절
  • ④ GROUP BY 절
상세 해설
정답은 ② WHERE 절입니다.
  • 논리적 수행 순서: FROM ➔ WHERE ➔ GROUP BY ➔ HAVING ➔ SELECT ➔ ORDER BY
  • SELECT 절은 나중에 실행되므로, 그보다 먼저 실행되는 WHERE, GROUP BY, HAVING 절에서는 SELECT의 별칭을 인식할 수 없습니다. 이 중 가장 먼저 실행되는 WHERE 절이 대표적인 오답 선지로 자주 출제됩니다. (반면 ORDER BY는 SELECT보다 나중이므로 별칭 사용이 가능합니다.)
Q17. ANSI 표준 조인 중에서, 두 테이블 간에 이름과 데이터 타입이 같은 모든 컬럼을 자동으로 찾아서 등가(Equi) 조인을 수행하는 것은?
  • ① CROSS JOIN
  • ② LEFT OUTER JOIN
  • ③ FULL OUTER JOIN
  • ④ NATURAL JOIN
상세 해설
정답은 ④ NATURAL JOIN입니다.
  • ① CROSS JOIN: 조인 조건 없이 양쪽 테이블의 모든 경우의 수를 곱(Cartesian Product)합니다.
  • ④ NATURAL JOIN: 동일한 이름을 가진 모든 컬럼을 찾아 자동으로 INNER JOIN 합니다. (이때 ON 조건절과 테이블 별칭(Alias)은 사용할 수 없습니다.)
Q18. A 테이블의 행이 5건, B 테이블의 행이 4건일 때 두 테이블을 CROSS JOIN (카티시안 곱) 한 결과의 총 행 수는?
  • ① 4건
  • ② 9건
  • ③ 20건
  • ④ 25건
상세 해설
정답은 ③ 20건입니다.
  • CROSS JOIN은 조인 조건이 없기 때문에 (A 테이블의 행 수) × (B 테이블의 행 수) 만큼의 데이터가 생성됩니다. (5 × 4 = 20건)
Q19. A LEFT OUTER JOIN B 를 수행할 때, 기준 테이블인 A의 데이터는 모두 출력되지만 조인 조건에 맞는 B 테이블의 데이터가 없다면 B의 컬럼들은 어떻게 출력되는가?
  • ① 0으로 치환되어 출력된다.
  • ② B 테이블의 값은 모두 NULL로 출력된다.
  • ③ 조인에 실패하므로 A 테이블의 데이터도 출력되지 않는다.
  • ④ 빈 문자열('')로 출력된다.
상세 해설
정답은 ② NULL 출력입니다.
  • OUTER JOIN의 특성상 기준이 되는 테이블(LEFT)의 데이터는 무조건 보존되며, 매칭되지 않는 반대편 테이블(B)의 값들은 모두 NULL로 채워져 결과가 반환됩니다.
Q20. SELECT 절 내부에 위치하며, 반드시 단일 행과 단일 컬럼의 값만을 반환해야 하는 서브쿼리를 무엇이라 하는가?
  • ① 스칼라 서브쿼리
  • ② 인라인 뷰
  • ③ 상관 서브쿼리
  • ④ 다중행 서브쿼리
상세 해설
정답은 ① 스칼라 서브쿼리입니다.
  • ① 스칼라 서브쿼리: SELECT 절에 위치하며 단 하나의 값만 반환해야 합니다.
  • ② 인라인 뷰 (Inline View): FROM 절에 위치하는 가상의 테이블입니다.
  • ③ 상관 서브쿼리: 메인 쿼리의 컬럼을 서브쿼리 내부로 끌어와 사용하는 구조의 쿼리입니다.
Q21. 서브쿼리의 결과가 2건 이상인 다중행 서브쿼리에서, 서브쿼리의 결과 중 "단 하나라도 만족하면 참(TRUE)"을 반환하는 다중행 연산자는?
  • ① ALL
  • ② EXISTS
  • ③ ANY (또는 SOME)
  • ④ =
상세 해설
정답은 ③ ANY (또는 SOME)입니다.
  • ① ALL: 서브쿼리의 '모든' 결과를 만족해야 참이 됩니다.
  • ② EXISTS: 서브쿼리의 결과가 1건이라도 '존재하는지' 여부만 판단합니다.
  • ③ ANY: 서브쿼리의 결과 중 '어느 하나라도' 조건(>, < 등)을 만족하면 참이 됩니다.
  • ④ = : 서브쿼리 결과가 1건일 때만 쓸 수 있는 단일행 연산자입니다.
Q22. 두 SELECT 쿼리의 결과를 합치는 집합 연산자 중에서, 중복된 데이터를 제거하고 결과 집합을 정렬(Sort)하여 반환하는 것은?
  • ① UNION
  • ② UNION ALL
  • ③ INTERSECT
  • ④ MINUS
상세 해설
정답은 ① UNION입니다.
  • ① UNION (합집합): 두 결과를 합칠 때 중복을 제거하기 위해 내부적으로 오버헤드가 큰 '정렬(Sort)' 작업을 반드시 수행합니다.
  • ② UNION ALL (단순결합): 중복 제거와 정렬 작업을 하지 않고 결과를 그대로 이어 붙이므로 속도가 훨씬 빠릅니다.
  • ③ INTERSECT: 교집합. ④ MINUS: 차집합.
Q23. 윈도우 함수 중, 동점자에게 동일한 순위를 부여하고 그 다음 순위는 동점자 수만큼 건너뛰어 부여하는 함수는? (예: 1등, 2등, 2등, 4등)
  • ① RANK()
  • ② DENSE_RANK()
  • ③ ROW_NUMBER()
  • ④ NTILE()
상세 해설
정답은 ① RANK()입니다.
  • ① RANK(): 1, 2, 2, 4 처럼 다음 순위를 건너뜁니다.
  • ② DENSE_RANK(): 1, 2, 2, 3 처럼 순위를 밀집(Dense)하게 채워 건너뛰지 않습니다.
  • ③ ROW_NUMBER(): 1, 2, 3, 4 처럼 동점자라도 무조건 고유한 일련번호를 매깁니다.
  • ④ NTILE(): 전체 데이터를 N개의 그룹으로 균등하게 분할(버킷팅)하는 함수입니다.
Q24. 윈도우 함수를 사용하여 순위를 구할 때, 순위를 건너뛰지 않고 1, 2, 2, 3 과 같이 촘촘하게 이어서 부여하는 함수는?
  • ① RANK()
  • ② DENSE_RANK()
  • ③ ROW_NUMBER()
  • ④ LAG()
상세 해설
정답은 ② DENSE_RANK()입니다.
  • 바로 위 Q23 해설에서 설명한 대로, 동점자가 있어도 등수를 건너뛰지 않고 밀도 있게(Dense) 부여하는 함수입니다.
Q25. 윈도우 함수에서 파티션 내의 정렬된 결과 중 '다음(이후) 행'의 값을 가져오기 위해 사용하는 함수는?
  • ① LAG()
  • ② LEAD()
  • ③ NEXT()
  • ④ FOLLOW()
상세 해설
정답은 ② LEAD()입니다.
  • ① LAG(): 현재 읽고 있는 행을 기준으로 '이전 행'의 값을 땡겨옵니다.
  • ② LEAD(): 현재 읽고 있는 행을 기준으로 '다음 행'의 값을 가져옵니다.
  • ③ NEXT, ④ FOLLOW: SQL 윈도우 함수에 존재하지 않는 명칭입니다.
Q26. 오라클 계층형 질의(Hierarchical Query)에서 트리의 전체 구조가 아닌, 동일한 레벨(형제 노드) 내에서만 정렬을 수행할 때 사용하는 키워드는?
  • ① ORDER BY
  • ② GROUP BY
  • ③ START WITH
  • ④ ORDER SIBLINGS BY
상세 해설
정답은 ④ ORDER SIBLINGS BY입니다.
  • ① ORDER BY: 계층 구조(부모-자식 트리)를 완전히 무시하고 전체 데이터를 단순 정렬해버립니다.
  • ③ START WITH: 트리를 어느 노드(Root)에서부터 시작할지 지정하는 절입니다.
  • ④ ORDER SIBLINGS BY: 계층 구조를 보존하면서, 부모가 같은 형제(Siblings) 노드들 끼리만 정렬을 수행합니다.
Q27. "CONNECT BY PRIOR 자식컬럼 = 부모컬럼" 으로 작성된 계층형 질의의 전개 방향은 어떻게 되는가?
  • ① 순방향 전개 (부모 ➔ 자식)
  • ② 역방향 전개 (자식 ➔ 부모)
  • ③ 수평 전개 (형제 간)
  • ④ 교차 전개
상세 해설
정답은 ② 역방향 전개입니다.
  • PRIOR 키워드가 붙은 쪽이 '현재 읽은 행'을 의미합니다.
  • 즉, `PRIOR 자식 = 부모`는 "현재 읽은 행이 자식 노드이고, 다음으로 부모 노드를 찾아가라"는 뜻이 되어 사원 ➔ 팀장 ➔ 사장 방향으로 거슬러 올라가는 역방향(Bottom-Up) 전개가 일어납니다.
Q28. 트랜잭션의 ACID 특성 중, "트랜잭션에 포함된 작업들은 모두 반영되거나(Commit) 모두 반영되지 않아야(Rollback) 한다"는 특성은?
  • ① 원자성 (Atomicity)
  • ② 고립성 (Isolation)
  • ③ 일관성 (Consistency)
  • ④ 지속성 (Durability)
상세 해설
정답은 ① 원자성입니다.
  • ① 원자성: All or Nothing 원칙입니다. 계좌 이체 시 '돈을 빼는 작업'과 '돈을 넣는 작업'은 쪼개질 수 없는 하나의 원자(Atom)처럼 묶여서 완벽히 성공하거나 완벽히 실패해야 합니다.
  • ② 고립성: 내 작업 중간에 남이 끼어들 수 없음. ③ 일관성: 제약조건 모순 없음. ④ 지속성: 완료 시 영구 보존됨.
Q29. 집계 함수인 SUM()의 동작 방식에 대한 설명으로 올바른 것은?
  • ① 연산 대상 컬럼에 NULL이 있으면 결과는 무조건 NULL이다.
  • ② 대상 데이터 중 NULL 값은 제외하고 합계를 계산한다.
  • ③ NULL 값을 0으로 자동 치환하여 계산한다.
  • ④ SUM 함수는 GROUP BY 절이 없으면 사용할 수 없다.
상세 해설
정답은 ② NULL 값 제외입니다.
  • ①: 단일 행의 숫자 덧셈(10 + NULL)은 NULL이지만, 다중 행 집계 함수(SUM, AVG 등)는 NULL 행을 쿨하게 버리고 계산합니다.
  • ③: AVG 계산 시 0으로 치환하면 분모가 늘어나 평균값이 깎이므로 자동 치환하지 않고 아예 해당 행을 제외합니다.
  • ④: GROUP BY 없이 쓰면 테이블 전체를 하나의 그룹으로 보고 총합계를 계산해 줍니다.
