Q01. 실무에서 가장 널리 사용되는 ERD 표기법으로, 엔터티 간의 관계 차수(다중성)를 표현할 때 '까마귀 발(Crow's Foot)' 모양을 사용하는 표기법은?
  • ① Barker 표기법
  • ② IE (Information Engineering) 표기법
  • ③ UML 표기법
  • ④ Chen 표기법
상세 해설
정답은 ② IE 표기법입니다.
  • ① Barker 표기법: Oracle에서 주로 사용하며, 다중성을 실선/점선과 닭발(까마귀발) 형태로 표현하지만, 보통 까마귀 발 표기법의 대명사로 시험에서는 IE 표기법을 정답으로 요구합니다. (정확히는 IE가 까마귀 발을 고안했습니다.)
  • ② IE 표기법: 관계를 실선/점선, 까마귀 발, 동그라미(선택) 등으로 직관적으로 표현하는 가장 대중적인 표기법입니다.
  • ③ UML: 객체지향 설계에서 클래스 다이어그램을 그릴 때 주로 사용합니다. (1..*)
  • ④ Chen 표기법: 마름모, 직사각형 등 도형을 이용하는 초기 ER 모델 표기법입니다.
Q02. 발생 시점에 따른 엔터티의 분류 중, "사원, 부서, 고객, 상품"과 같이 업무에 원래 존재하며 다른 엔터티의 부모 역할을 하는 가장 독립적인 엔터티는?
  • ① 기본 엔터티 (Fundamental Entity) / 키 엔터티
  • ② 중심 엔터티 (Main Entity)
  • ③ 행위 엔터티 (Action Entity)
  • ④ 파생 엔터티 (Derived Entity)
상세 해설
정답은 ① 기본 엔터티입니다.
  • ① 기본 엔터티: 업무에 원래 존재하는 정보로, 다른 엔터티로부터 파생되지 않고 독립적으로 생성됩니다.
  • ② 중심 엔터티: 기본 엔터티로부터 발생하며(예: 주문, 계약), 행위 엔터티를 생성하는 중간 역할입니다.
  • ③ 행위 엔터티: 두 개 이상의 부모 엔터티로부터 발생하며, 자주 변경되고 데이터양이 가장 많습니다. (예: 주문 상세내역)
  • ④ 파생 엔터티: 이런 분류 명칭은 없습니다. (파생 '속성'은 존재함)
Q03. 주소(시+구+동)와 같이 여러 개의 세부 의미가 합쳐져서 하나의 속성을 이루는 속성의 명칭은?
  • ① 단일 속성 (Simple Attribute)
  • ② 복합 속성 (Composite Attribute)
  • ③ 다중값 속성 (Multi-Valued Attribute)
  • ④ 파생 속성 (Derived Attribute)
상세 해설
정답은 ② 복합 속성입니다.
  • ① 단일 속성: 더 이상 쪼개질 수 없는 속성입니다.
  • ② 복합 속성: 쪼개면 여러 개의 독립적인 의미(시, 구, 동)를 가지는 속성입니다.
  • ③ 다중값 속성: 한 속성에 여러 개의 값(예: 한 사람의 전화번호 3개)을 가질 수 있는 속성으로, 제1정규화의 대상이 됩니다.
  • ④ 파생 속성: 계산되어 만들어진 속성입니다.
Q04. 식별자(Identifier)의 대체 여부에 따른 분류 중, 원래 업무에서 자연스럽게 만들어진 식별자가 복잡하여 인위적으로 '일련번호'나 '코드'를 부여한 식별자는?
  • ① 본질 식별자
  • ② 인조 식별자 (Surrogate Identifier)
  • ③ 외부 식별자
  • ④ 보조 식별자
상세 해설
정답은 ② 인조 식별자입니다.
  • ① 본질 식별자: 주민등록번호나 사번처럼 실제 업무에서 의미를 가지고 생성되는 식별자입니다.
  • ② 인조 식별자: 본질 식별자가 너무 길거나 복잡할 때, 시스템 성능이나 편의를 위해 인위적으로 만든 '주문번호_SEQ' 같은 일련번호 식별자입니다.
  • ③ 외부 식별자: 타 테이블의 PK를 참조하는 외래키(FK)입니다.
  • ④ 보조 식별자: 주식별자를 대신할 수는 있지만 대표성을 띠지 못하는 식별자입니다.
Q05. "회원 테이블의 '취미' 컬럼에 '독서, 영화감상, 등산'처럼 여러 개의 값이 콤마(,)로 구분되어 들어가 있다." 이 테이블은 어떤 정규화 원칙을 위반한 것인가?
  • ① 제1정규형 (1NF)
  • ② 제2정규형 (2NF)
  • ③ 제3정규형 (3NF)
  • ④ 제4정규형 (4NF)
상세 해설
정답은 ① 제1정규형 (1NF)입니다.
  • 제1정규형(1NF): 릴레이션의 모든 속성은 단일 값(원자성)만을 가져야 합니다. 다중값 속성(여러 개의 값)을 가지면 제1정규화 위반이므로 별도의 테이블로 쪼개야 합니다.
Q06. 반정규화(Denormalization) 기법 중, 데이터양이 너무 많아 성능이 저하되는 것을 막기 위해 테이블을 행(Row) 단위로 쪼개거나 열(Column) 단위로 쪼개어 물리적인 파티션을 나누는 기법은?
  • ① 테이블 병합
  • ② 테이블 분할 (수평/수직 분할)
  • ③ 컬럼 중복
  • ④ 관계 중복
상세 해설
정답은 ② 테이블 분할입니다.
  • ① 테이블 병합: 조인 횟수를 줄이기 위해 두 테이블을 하나로 합치는 반정규화입니다.
  • ② 테이블 분할: 데이터가 너무 방대할 때 성능을 위해 행을 쪼개는 '수평 분할(파티셔닝)'과 특정 컬럼만 자주 조회될 때 열을 쪼개는 '수직 분할'이 있습니다.
  • ③, ④: 컬럼이나 관계를 의도적으로 중복시켜 조인을 피하는 방법입니다.
Q07. 데이터베이스의 3단계 스키마 구조 중, "모든 사용자의 관점을 통합한 조직 전체의 데이터베이스 논리적 구조"를 의미하는 것은?
  • ① 외부 스키마 (External Schema)
  • ② 개념 스키마 (Conceptual Schema)
  • ③ 내부 스키마 (Internal Schema)
  • ④ 통합 스키마 (Integrated Schema)
상세 해설
정답은 ② 개념 스키마입니다.
  • ① 외부 스키마: 개별 사용자나 응용 프로그램 관점.
  • ② 개념 스키마: 모든 관점을 통합한 전사적 관점 (ERD가 여기에 해당).
  • ③ 내부 스키마: 물리적인 디스크 저장 구조 관점.
Q08. 속성(Attribute)의 명명 규칙(Naming Rule)으로 가장 부적절한 것은?
  • ① 타이핑의 편의를 위해 의미가 명확하지 않더라도 최대한 약어(Abbreviation)를 많이 사용한다.
  • ② 현업에서 사용하는 친숙한 업무 용어를 사용한다.
  • ③ 전체 데이터 모델 내에서 속성명은 가급적 유일(Unique)해야 한다.
  • ④ 수식어, 소유격 등을 사용하여 속성의 의미를 구체적으로 명시한다.
상세 해설
정답은 ①입니다.
  • ① (오답): 약어 사용은 최대한 자제해야 하며, 불가피하게 사용할 경우 전사적으로 표준화된 약어만 사용해야 혼란을 막을 수 있습니다.
  • ③: 속성명이 유일하면 향후 데이터 추적과 통합이 매우 쉬워집니다.
Q09. 엔터티 간의 관계를 정의하는 '관계의 3대 요소'에 해당하지 않는 것은?
  • ① 관계명 (Relationship Name)
  • ② 관계차수 (Degree / Cardinality)
  • ③ 관계선택사양 (Optionality)
  • ④ 식별자 속성 (Identifier Attribute)
상세 해설
정답은 ④ 식별자 속성입니다.
  • 관계의 3대 요소는 관계명(소속된다, 포함한다), 관계차수(1:1, 1:M, M:N), 관계선택사양(필수/선택)입니다. 식별자 속성은 '엔터티'의 구성 요소입니다.
Q10. 데이터 독립성(Data Independence)을 확보했을 때 얻을 수 있는 장점이 아닌 것은?
  • ① 데이터베이스 시스템의 유지보수 비용이 절감된다.
  • ② 데이터 모델의 복잡도가 증가하여 시스템 보안성이 강화된다.
  • ③ 하위 스키마가 변경되어도 상위 스키마의 응용 프로그램을 수정할 필요가 없다.
  • ④ 데이터의 중복성을 줄이고 무결성을 유지하기 쉬워진다.
상세 해설
정답은 ② 복잡도 증가입니다.
  • 데이터 독립성의 주 목적은 '복잡도를 감소'시키고 유연성을 확보하는 것입니다. 독립성이 보장되면 물리적 구조가 바뀌어도 응용 프로그램 코드(외부 스키마)를 뜯어고칠 필요가 없으므로 유지보수 비용이 획기적으로 줄어듭니다.

Q11. 데이터 제어어(DCL)에 해당하는 명령어로 짝지어진 것은?
  • ① GRANT, REVOKE
  • ② COMMIT, ROLLBACK
  • ③ CREATE, DROP
  • ④ INSERT, UPDATE
상세 해설
정답은 ① GRANT, REVOKE입니다.
  • ① DCL (Data Control Language): 유저에게 권한을 부여(GRANT)하거나 회수(REVOKE)합니다.
  • ② TCL: 트랜잭션 제어 (COMMIT, ROLLBACK, SAVEPOINT).
  • ③ DDL: 데이터 정의어 (CREATE, ALTER, DROP, TRUNCATE).
  • ④ DML: 데이터 조작어 (SELECT, INSERT, UPDATE, DELETE).
Q12. 기존에 생성된 테이블에 새로운 컬럼(Column)을 추가할 때 사용하는 DDL 명령어는?
  • ① ALTER TABLE ~ ADD
  • ② ALTER TABLE ~ MODIFY
  • ③ ALTER TABLE ~ DROP
  • ④ CREATE TABLE ~ ADD
상세 해설
정답은 ① ALTER TABLE ~ ADD입니다.
  • ① ADD: 새로운 컬럼 추가.
  • ② MODIFY: 기존 컬럼의 데이터 타입이나 크기 변경.
  • ③ DROP: 기존 컬럼 삭제.
Q13. LIKE 연산자에서 '어떤 문자든 정확히 1개의 문자'를 의미하는 와일드카드 기호는?
  • ① %
  • ② _ (언더바)
  • ③ *
  • ④ ?
상세 해설
정답은 ② _ (언더바)입니다.
  • % (퍼센트): 0개 이상의 모든 문자열을 의미합니다. (예: '김%' = 김으로 시작하는 모든 글자)
  • _ (언더바): 정확히 1개의 문자를 의미합니다. (예: '김__' = 김으로 시작하는 3글자 이름)
Q14. 테이블 T1의 COL1에 데이터 `[10, 20, NULL, 40]`이 있을 때, `SELECT COUNT(COL1) FROM T1;` 의 결과는?
  • ① 3
  • ② 4
  • ③ NULL
  • ④ 에러 발생
상세 해설
정답은 ① 3입니다.
  • COUNT(*)는 NULL을 포함한 전체 행 수(4)를 반환하지만, COUNT(특정컬럼)은 해당 컬럼 값이 NULL인 행을 제외하고 카운트합니다.
Q15. Oracle에서 데이터를 1건만 가져오기 위해 `WHERE ROWNUM = 2;` 조건을 주었을 때 반환되는 결과는?
  • ① 2번째 행이 출력된다.
  • ② 맨 처음 2개의 행이 출력된다.
  • ③ 아무 데이터도 출력되지 않는다 (0건).
  • ④ 쿼리 문법 에러가 발생한다.
상세 해설
정답은 ③ 아무 데이터도 출력되지 않는다입니다.
  • 오라클의 ROWNUM은 데이터를 읽어올 때마다 순차적으로 1부터 번호를 부여하는 가상 컬럼입니다. 1번을 읽어야만 2번이 생성되므로, WHERE ROWNUM = 2 또는 WHERE ROWNUM > 1 조건은 영원히 만족할 수 없어 데이터가 0건 출력됩니다.
    (반면 WHERE ROWNUM = 1 이나 <= 2는 정상 동작합니다.)
Q16. 다중행 서브쿼리의 결과와 비교할 때, 반환된 여러 개의 값 중 "일치하는 것이 있는지" 목록(List) 안에서 검사하는 다중행 연산자는?
  • ① IN
  • ② BETWEEN
  • ③ =
  • ④ LIKE
상세 해설
정답은 ① IN입니다.
  • ① IN: 서브쿼리가 반환한 여러 개의 값들(List) 중 하나라도 일치하는 것이 있는지 비교합니다. (다중행 연산자: IN, ANY, ALL, EXISTS)
  • ③ = : 단일행 서브쿼리 연산자이므로, 서브쿼리 결과가 2개 이상일 때 사용하면 ORA-01427 에러가 발생합니다.
Q17. A와 B 테이블을 조인할 때, 조인 조건에 일치하지 않는 양쪽 테이블의 모든 데이터를 누락 없이 100% 보존하여 출력하는 조인 방식은?
  • ① INNER JOIN
  • ② LEFT OUTER JOIN
  • ③ RIGHT OUTER JOIN
  • ④ FULL OUTER JOIN
상세 해설
정답은 ④ FULL OUTER JOIN입니다.
  • LEFT OUTER(왼쪽 보존), RIGHT OUTER(오른쪽 보존)의 결과를 합친 것과 같으며, 양쪽 테이블의 모든 데이터를 보존하고 매칭되지 않는 빈칸은 NULL로 출력합니다.
Q18. 집합 연산자 중 두 쿼리의 결과 집합에서 '공통으로 존재하는 교집합 데이터'만 추출하는 연산자는?
  • ① UNION
  • ② UNION ALL
  • ③ INTERSECT
  • ④ MINUS (EXCEPT)
상세 해설
정답은 ③ INTERSECT입니다.
  • ① UNION / ② UNION ALL: 합집합
  • ③ INTERSECT: 교집합 (중복 제거 정렬 발생)
  • ④ MINUS: 차집합 (A결과에는 있고 B결과에는 없는 것)
Q19. 일반적인 GROUP BY 절과 윈도우 함수 내의 PARTITION BY 절의 가장 큰 차이점은?
  • ① PARTITION BY는 데이터를 집계(합계, 평균 등)할 수 없다.
  • ② GROUP BY는 원본 데이터의 행 수를 그룹화하여 줄이지만, PARTITION BY는 원본 데이터의 행 수를 그대로 유지하면서 그룹 연산만 수행한다.
  • ③ GROUP BY는 WHERE 절 다음에만 쓸 수 있지만, PARTITION BY는 FROM 절에서 쓴다.
  • ④ 두 구문 간의 결과 차이는 전혀 없다.
상세 해설
정답은 ② 행 수 유지 여부입니다.
  • GROUP BY: 10명의 사원 데이터를 부서별로 묶으면 결과가 3줄(부서 개수)로 확 줄어듭니다.
  • PARTITION BY (윈도우 함수): 각 사원의 개별 정보(10줄)를 그대로 유지한 채로, 그 옆에 '자신이 속한 부서의 평균 급여' 같은 그룹 연산 결과를 나란히 붙여서 보여줍니다.
Q20. 다음 윈도우 함수 쿼리 `SUM(매출) OVER(PARTITION BY 지점 ORDER BY 월)`의 결과 특성은 무엇인가?
  • ① 지점별 전체 매출 합계를 모든 행에 동일하게 출력한다.
  • ② 지점별로 월 순서에 따라 차곡차곡 더해지는 '누적 합계(Cumulative Sum)'를 출력한다.
  • ③ 월별 전체 지점의 매출 합계를 구한다.
  • ④ 에러가 발생한다.
상세 해설
정답은 ② 누적 합계입니다.
  • 윈도우 함수에서 집계함수(SUM, COUNT 등) 뒤에 ORDER BY가 함께 쓰이면, 기본적으로 첫 행부터 현재 행까지의 누적 연산(Running Total)을 수행하게 됩니다.
  • 만약 ORDER BY를 빼고 SUM(매출) OVER(PARTITION BY 지점)만 쓴다면 ①번 설명처럼 해당 지점의 전체 총합이 동일하게 출력됩니다.
Q21. 계층형 질의(Hierarchical Query)에서 현재 노드의 깊이(Depth, 몇 번째 계층인지)를 알려주는 오라클 가상 컬럼(Pseudo Column)은?
  • ① ROWNUM
  • ② LEVEL
  • ③ CONNECT_BY_ISLEAF
  • ④ ROWID
상세 해설
정답은 ② LEVEL입니다.
  • 계층형 질의에서 START WITH로 지정된 최상위 루트 노드는 LEVEL 1을 가집니다. 그 아래 자식으로 내려갈 때마다 LEVEL이 2, 3... 으로 1씩 증가합니다. 이를 이용해 조직도 앞에 들여쓰기(LPAD)를 구현할 수 있습니다.
Q22. 오라클(Oracle)에서 ORDER BY를 사용한 정렬 시, NULL 데이터의 기본 위치에 대한 설명으로 올바른 것은?
  • ① DESC (내림차순) 정렬 시 NULL은 맨 처음에 (NULLS FIRST) 출력된다.
  • ② ASC (오름차순) 정렬 시 NULL은 맨 처음에 (NULLS FIRST) 출력된다.
  • ③ 오라클에서 NULL은 항상 최소값으로 취급된다.
  • ④ SQL Server와 오라클의 NULL 처리 위치는 완전히 동일하다.
상세 해설
정답은 ① DESC 시 맨 처음 출력입니다.
  • 오라클은 NULL을 '무한히 큰 값'으로 간주합니다.
  • 따라서 ASC(오름차순: 작은것➔큰것) 정렬을 하면 가장 큰 값인 NULL이 맨 마지막(NULLS LAST)에 출력됩니다.
  • 반대로 DESC(내림차순: 큰것➔작은것) 정렬을 하면 가장 큰 값인 NULL이 맨 처음(NULLS FIRST)에 출력됩니다.
Q23. 오라클에서 IF-THEN-ELSE 논리를 SQL 문장 내에 구현하기 위해 사용하며, ANSI 표준인 CASE 문과 동일한 역할을 하는 오라클 전용 함수는?
  • ① DECODE
  • ② NVL
  • ③ REPLACE
  • ④ SUBSTR
상세 해설
정답은 ① DECODE입니다.
  • DECODE(컬럼, A, 1, B, 2, 3) = "컬럼 값이 A이면 1, B이면 2, 아니면 3을 반환하라".
  • 이 함수는 오라클에서만 동작하므로, 다른 DB와의 호환성을 위해서는 표준 문법인 CASE WHEN ~ THEN 구문을 사용하는 것이 좋습니다.
Q24. DDL(데이터 정의어) 명령어의 트랜잭션 특성에 대한 설명으로 올바른 것은?
  • ① 실행 즉시 Auto Commit 처리되므로 이후에 ROLLBACK 할 수 없다.
  • ② 수행 후 사용자가 명시적으로 COMMIT을 입력해야만 DB에 반영된다.
  • ③ 테이블 내의 데이터 건수가 많을 경우 ROLLBACK이 허용된다.
  • ④ DML 명령어와 동일하게 SAVEPOINT를 통한 부분 취소가 가능하다.
상세 해설
정답은 ① Auto Commit 발생입니다.
  • CREATE, DROP, ALTER, TRUNCATE 같은 DDL 명령어는 실행되는 즉시 내부적으로 Commit이 발생(Auto Commit)하여 데이터베이스 사전에 영구 반영됩니다. 따라서 절대 롤백할 수 없습니다.
Q25. 조인 문법 중 `USING (컬럼명)` 조건절을 사용할 때의 규칙으로 올바른 것은?
  • ① 조인하려는 두 테이블의 컬럼 이름이 달라도 사용할 수 있다.
  • ② USING 절에 사용된 컬럼은 SELECT 절에서 테이블 별칭(Alias)을 붙여서 표기할 수 없다 (예: A.DEPTNO 불가).
  • ③ 다중 컬럼은 USING 절로 묶을 수 없다.
  • ④ NATURAL JOIN과 함께 섞어서 사용할 수 있다.
상세 해설
정답은 ② 테이블 별칭(Alias) 사용 불가입니다.
  • USING이나 NATURAL JOIN의 기준이 된 공통 컬럼은 두 테이블이 합쳐진 공통의 영역으로 취급되므로, SELECT A.DEPTNO 처럼 특정 테이블의 식별자(Prefix)를 붙이면 에러가 발생합니다. (그냥 SELECT DEPTNO 라고 써야 함)
  • ①: 컬럼 이름이 반드시 동일해야만 USING을 쓸 수 있습니다. 다르면 ON을 써야 합니다.
Q26. 테이블의 행(Row) 데이터를 열(Column) 데이터로 회전시켜 교차표(Cross-tab) 형태로 데이터를 재구성하는 함수(기능)는?
  • ① PIVOT
  • ② UNPIVOT
  • ③ ROLLUP
  • ④ CUBE
상세 해설
정답은 ① PIVOT입니다.
  • ① PIVOT: 세로로 길게 쌓인 행(Row) 데이터를 가로(Column) 방향으로 펼쳐서 요약 보고서 형태로 만드는 기능입니다.
  • ② UNPIVOT: 반대로 가로로 넓게 퍼진 열(Column) 데이터를 세로(Row) 방향으로 내리는 기능입니다.
  • ③ ROLLUP / CUBE: GROUP BY와 함께 쓰여 소계(Subtotal)와 총계를 구해주는 그룹 함수입니다.
Q27. 문자열 조작 함수 중 `LTRIM(' SQLD ')`을 실행한 결과는? (단, 공백을 1칸으로 간주)
  • ① 'SQLD ' (왼쪽 공백만 제거됨)
  • ② ' SQLD' (오른쪽 공백만 제거됨)
  • ③ 'SQLD' (양쪽 공백 모두 제거됨)
  • ④ ' SQLD ' (아무런 변화 없음)
상세 해설
정답은 ① 'SQLD '입니다.
  • LTRIM (Left Trim): 문자열의 왼쪽(앞쪽)에 있는 공백(지정문자)을 제거합니다.
  • RTRIM: 오른쪽(뒤쪽) 공백 제거 / TRIM: 양쪽 공백 모두 제거.
Q28. 다중 컬럼 서브쿼리(Multi-Column Subquery)를 사용할 때 메인 쿼리와 비교하기 위해 사용하는 연산자는? (예: `WHERE (컬럼1, 컬럼2) ? (SELECT ...)`)
  • ① IN
  • ② >
  • ③ LIKE
  • ④ BETWEEN
상세 해설
정답은 ① IN입니다.
  • 서브쿼리가 여러 개의 컬럼을 묶어서 반환할 때, 메인 쿼리에서도 괄호로 묶어서 (A, B) IN (SELECT X, Y ...) 형태로 비교해야 합니다. 이때 쌍을 이루어 일치하는지 확인하기 위해 주로 IN 연산자를 사용합니다. (SQL Server에서는 다중 컬럼 서브쿼리를 지원하지 않는 경우가 많음)
Q29. 다음 순위(윈도우) 함수 중 "동점자 여부와 상관없이 무조건 1, 2, 3, 4번의 고유한 일련번호를 부여"하는 함수는?
  • ① RANK()
  • ② DENSE_RANK()
  • ③ ROW_NUMBER()
  • ④ NTILE()
상세 해설
정답은 ③ ROW_NUMBER()입니다.
  • 이름 그대로 행(Row)의 번호를 매깁니다. 점수가 100점으로 똑같은 사람이 2명 있어도, 테이블에서 읽힌 순서(또는 추가 정렬 기준)에 따라 강제로 1등과 2등을 나누어 고유한 번호를 부여합니다. 게시판 페이징 처리에 자주 쓰입니다.
Q30. 데이터베이스 내의 기존 테이블 이름을 변경할 때 사용하는 DDL 명령어는?
  • ① RENAME (또는 ALTER TABLE ~ RENAME TO)
  • ② MODIFY
  • ③ CHANGE
  • ④ UPDATE
상세 해설
정답은 ① RENAME입니다.
  • 테이블의 이름을 변경할 때는 DDL인 RENAME 기존테이블명 TO 새테이블명 (오라클)을 사용합니다.
  • UPDATE는 DML이므로 '테이블 이름'이 아니라 테이블 내부의 '데이터 값'을 변경할 때 사용합니다.
