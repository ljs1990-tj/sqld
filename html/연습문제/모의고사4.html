📚 제 1과목 : 데이터 모델링의 이해 (10문제)
Q01. 데이터 모델링의 3가지 관점(View)에 대한 설명으로 가장 적절하지 않은 것은?
  • ① 데이터 관점(Data View)은 업무가 어떤 데이터와 관련이 있는지, 데이터 간의 관계는 무엇인지를 모델링한다.
  • ② 프로세스 관점(Process View)은 업무가 실제로 무슨 일을 하고 있는지, 또는 무엇을 해야 하는지를 모델링한다.
  • ③ 데이터와 프로세스의 상관 관점(Data vs Process View)은 프로세스의 흐름에 따라 데이터가 어떤 영향을 받고 변하는지를 모델링한다.
  • ④ 데이터 모델링을 수행할 때는 이 3가지 관점을 순차적인 단계(데이터 ➔ 프로세스 ➔ 상관)로 분리하여 독립적으로 완성해야 한다.
상세 해설
정답은 ④입니다.
  • ①, ②, ③ (옳은 선지): 데이터, 프로세스, 데이터-프로세스 상관 관점의 정의를 정확히 설명하고 있습니다.
  • ④ (틀린 선지): 데이터 모델링 시 이 3가지 관점은 분리되어 독립적으로 수행되는 것이 아니라, 상호 연관성을 가지며 병행(또는 복합적)으로 진행되어야 시스템의 무결성과 일관성을 확보할 수 있습니다.
Q02. 엔터티(Entity)의 특징과 정의에 대한 설명 중 가장 거리가 먼 것은?
  • ① 엔터티는 업무에 필요하고 유용한 정보를 저장하고 관리하기 위한 집합적인 개념이다.
  • ② 엔터티는 반드시 두 개 이상의 속성(Attribute)을 가져야 하며, 단일 속성만으로는 엔터티가 성립될 수 없다.
  • ③ 엔터티는 반드시 다른 엔터티와 최소 한 개 이상의 관계(Relationship)를 맺어야 한다. (단, 통계성 엔터티나 코드성 엔터티는 예외)
  • ④ 엔터티를 도출할 때는 시스템 설계자의 임의적인 판단을 최우선으로 하여 성능 중심의 인위적 집합을 만들어야 한다.
상세 해설
정답은 ④입니다.
  • ①, ②, ③ (옳은 선지): 엔터티는 유용한 정보의 집합이며, 2개 이상의 속성과 인스턴스를 가져야 하고, 고립되지 않고 최소 1개 이상의 관계를 맺어야 한다는 핵심 특징들입니다.
  • ④ (틀린 선지): 엔터티는 설계자의 임의적 판단이 아니라 실제 '업무(Business)'에서 필요로 하는 정보를 바탕으로 도출해야 합니다. 물리적 성능 중심의 인위적 집합은 논리 모델링 이후의 '반정규화'나 물리 모델링 단계에서 검토할 사항입니다.
Q03. 속성(Attribute)의 특성에 따른 분류 중, 원래 업무에는 존재하지 않지만 시스템 설계를 위해 인위적으로 부여한 '코드(Code)'나 '일련번호(Sequence)' 같은 속성은 어디에 해당하는가?
  • ① 기본 속성 (Basic Attribute)
  • ② 설계 속성 (Designed Attribute)
  • ③ 파생 속성 (Derived Attribute)
  • ④ 복합 속성 (Composite Attribute)
상세 해설
정답은 ② 설계 속성입니다.
  • ① 기본 속성: 이름, 나이, 금액 등 업무 분석을 통해 가장 일반적이고 자연스럽게 도출되는 속성입니다.
  • ② 설계 속성: 식별의 편의나 시스템 성능 향상을 위해 업무에는 없었지만 설계자가 인위적으로 만들어낸 속성(예: 주문번호, 상품코드 등)입니다.
  • ③ 파생 속성: 다른 속성값으로부터 계산되거나 유도된 속성(예: 총합계, 평균)입니다.
Q04. 데이터 정규화(Normalization)에 대한 다음 설명 중, 정규형(NF)과 그 조건이 올바르게 짝지어지지 않은 것은?
  • ① 제1정규형(1NF) : 릴레이션의 모든 속성 값이 원자값(단일 값)이어야 하며, 반복되는 그룹이 없어야 한다.
  • ② 제2정규형(2NF) : 주식별자가 단일 속성일 경우에도 항상 부분 함수 종속성 검사를 수행하여 테이블을 분리해야 한다.
  • ③ 제3정규형(3NF) : 일반 속성 간에 함수 종속성(이행 함수 종속)이 존재하지 않아야 한다.
  • ④ BCNF(Boyce-Codd) : 모든 결정자는 반드시 후보키(Candidate Key)여야 한다.
상세 해설
정답은 ②입니다.
  • ①, ③, ④ (옳은 선지): 각 정규형의 핵심 정의를 완벽히 짚고 있습니다.
  • ② (틀린 선지): 제2정규형은 '기본키가 복합키(2개 이상의 속성 결합)일 때' 그 중 일부 속성에만 종속되는 부분 함수 종속을 제거하는 과정입니다. 따라서 기본키가 단일 속성이면 제2정규형은 자동으로 만족하므로 분리할 필요가 없습니다.
Q05. 주식별자의 특징(도출 기준) 4가지에 대한 설명으로 가장 올바르지 않은 것은?
  • ① 유일성: 주식별자로 지정된 속성 값은 엔터티 내의 모든 인스턴스를 유일하게 구분할 수 있어야 한다.
  • ② 최소성: 주식별자를 구성하는 속성의 수는 유일성을 만족하는 최소의 개수여야 한다.
  • ③ 존재성: 주식별자 속성에는 반드시 값이 존재해야 하며, NULL 값이 허용되지 않는다.
  • ④ 불변성: 주식별자의 값은 업무 프로세스에 따라 빈번하게 갱신(Update)되어 최신 상태를 유지해야 한다.
상세 해설
정답은 ④입니다.
  • ①, ②, ③ (옳은 선지): 유일성, 최소성, 존재성(NOT NULL)은 주식별자가 갖춰야 할 필수 요건입니다.
  • ④ (틀린 선지): 불변성(Invariability)이란 주식별자로 지정된 값이 한 번 부여되면 가급적 변경되지 않아야 함을 의미합니다. 빈번하게 갱신되면 연관된 자식 테이블들의 외래키(FK)까지 모조리 수정해야 하는 치명적인 오버헤드가 발생합니다.
Q06. 식별자 관계(Identifying)와 비식별자 관계(Non-Identifying)에 대한 설명 중 가장 적절한 것은?
  • ① 부모 엔터티의 주식별자를 자식 엔터티의 일반 속성으로 상속받는 것을 식별자 관계라고 한다.
  • ② 식별자 관계로만 전체 데이터 모델을 구성하면 하위 엔터티로 갈수록 주식별자의 속성 수가 감소하여 쿼리가 단순해진다.
  • ③ 비식별자 관계는 자식 엔터티가 부모 엔터티의 존재 여부와 무관하게 독립적으로 생명주기를 가질 때 주로 사용된다.
  • ④ ERD 표기법(IE 기준)에서 식별자 관계는 점선으로 표기하고, 비식별자 관계는 실선으로 표기한다.
상세 해설
정답은 ③입니다.
  • ③ (옳은 선지): 부모의 식별자를 일반 속성으로만 내려받는 비식별자 관계는 약한 종속성을 의미하므로, 자식 인스턴스가 부모와 독립적인 생명주기를 가질 때(부모가 삭제되어도 자식은 남아있을 때) 사용하기 적합합니다.
  • ① (틀린 선지): 일반 속성으로 받는 것은 '비식별자 관계'입니다. (식별자 관계는 PK의 일부로 포함시킴)
  • ② (틀린 선지): 식별자 관계는 하위로 갈수록 부모의 PK들이 계속 누적되므로 주식별자의 속성 수가 무한정 **증가(증식)**하여 쿼리가 매우 복잡해집니다.
  • ④ (틀린 선지): 식별자 관계는 실선(Solid Line), 비식별자 관계는 점선(Dashed Line)입니다.
Q07. 반정규화(Denormalization) 기법 중 테이블을 수평 분할(파티셔닝)하거나 수직 분할하는 목적과 거리가 먼 것은?
  • ① 데이터양이 너무 많아져 인덱스의 크기가 비대해지고 조회 성능이 저하되는 것을 막기 위해 수평 분할을 적용한다.
  • ② 특정 컬럼들만 집중적으로 자주 조회될 때, I/O 경합을 줄이기 위해 테이블을 수직 분할하여 분산시킨다.
  • ③ 테이블 분할을 수행하면 데이터 무결성을 실시간으로 완벽하게 보장할 수 있는 장점이 추가된다.
  • ④ 논리적 데이터 모델 단계에서의 정규화가 완료된 이후, 물리적인 디스크 I/O 성능 향상을 목적으로 적용한다.
상세 해설
정답은 ③입니다.
  • ①, ②, ④ (옳은 선지): 테이블 분할(수평/수직)은 데이터 대용량화로 인한 디스크 I/O 부하를 줄이고 성능을 향상하기 위한 물리적인 반정규화 기법입니다.
  • ③ (틀린 선지): 반정규화 기법(분할, 병합, 중복)은 본질적으로 데이터가 분산되거나 중복을 허용하기 때문에, 데이터 무결성 유지가 매우 어려워진다(손상될 수 있다)는 치명적인 단점을 가집니다. 무결성 보장은 오직 철저한 '정규화'를 통해서만 가능합니다.
Q08. 분산 데이터베이스(Distributed Database)의 4대 투명성(Transparency)에 해당하지 않는 것은?
  • ① 분할 투명성 (Fragmentation Transparency)
  • ② 위치 투명성 (Location Transparency)
  • ③ 중복 투명성 (Replication Transparency)
  • ④ 관계 투명성 (Relation Transparency)
상세 해설
정답은 ④입니다.
  • 분산 데이터베이스는 사용자가 분산된 환경을 눈치채지 못하게 하는 여러 '투명성'을 제공합니다.
  • 주요 투명성으로는 분할 투명성, 위치 투명성, 지역사상 투명성, 중복 투명성, 장애 투명성, 병행 투명성 등이 있습니다.
  • ④ 관계 투명성: 데이터베이스 용어에 존재하지 않는 함정 선지입니다.
Q09. 데이터베이스 트랜잭션의 4가지 특성(ACID)에 대한 설명 중 잘못된 것은?
  • ① 원자성(Atomicity): 트랜잭션 내의 모든 연산은 완전히 수행되거나 전혀 수행되지 않아야 한다(All or Nothing).
  • ② 일관성(Consistency): 트랜잭션 수행이 완료된 후에는 데이터베이스가 항상 일관된 무결성 상태를 유지해야 한다.
  • ③ 고립성(Isolation): 여러 트랜잭션이 동시에 실행될 때, 서로의 연산 과정에 끼어들거나 영향을 줄 수 없다.
  • ④ 지속성(Durability): 트랜잭션 도중 시스템 장애가 발생하더라도, 복구 프로세스 없이 변경 중인 데이터가 영구히 보존되어야 한다.
상세 해설
정답은 ④입니다.
  • ①, ②, ③ (옳은 선지): 원자성, 일관성, 고립성의 완벽한 정의입니다.
  • ④ (틀린 선지): 지속성(Durability)은 '성공적으로 완료(Commit)된' 트랜잭션의 결과가 영구적으로 보존되어야 함을 의미합니다. 트랜잭션 도중(Commit 되기 전) 장애가 나면 보존되는 것이 아니라 당연히 롤백(Rollback)되어 원상 복구되어야 합니다.
Q10. 속성의 도메인(Domain)에 대한 설명으로 가장 올바른 것은?
  • ① 엔터티를 구성하는 개별 데이터의 구체적인 값(예: 홍길동, 25)을 도메인이라고 부른다.
  • ② 하나의 속성이 가질 수 있는 값의 범위(데이터 타입, 크기, 제약조건 등)의 논리적인 집합을 의미한다.
  • ③ 도메인이 다르면 데이터 타입이 같더라도 두 속성 간에 조인(Join)을 수행할 수 없다.
  • ④ 도메인은 물리적 모델링 단계에서만 정의되며, 논리적 모델링 단계에서는 고려하지 않는다.
상세 해설
정답은 ②입니다.
  • ② (옳은 선지): 도메인은 특정 속성이 취할 수 있는 유효한 값의 범위(집합)입니다. (예: 성별 속성의 도메인은 '남', '여')
  • ① (틀린 선지): 개별 데이터 값은 도메인이 아니라 '속성값(Value)' 또는 '인스턴스(Instance)의 값'입니다.
  • ③ (틀린 선지): 도메인이 다르더라도(예: '사원번호'와 '부서번호') 데이터 타입만 같다면 문법적으로 조인은 성립합니다. (물론 논리적으로는 무의미한 결과가 나옴)
  • ④ (틀린 선지): 도메인은 논리적 데이터 모델링 단계에서 속성의 특성을 파악하기 위해 적극적으로 정의되어야 합니다.

Q11. 오라클(Oracle) 환경에서 ROWNUM에 대한 조건절 필터링 결과로 데이터가 항상 **0건(추출되지 않음)**이 나오는 쿼리는?
  • ① `SELECT * FROM emp WHERE ROWNUM = 1;`
  • ② `SELECT * FROM emp WHERE ROWNUM <= 5;`
  • ③ `SELECT * FROM emp WHERE ROWNUM > 1;`
  • ④ `SELECT * FROM emp WHERE ROWNUM < 3;`
상세 해설
정답은 ③입니다.
  • 오라클의 `ROWNUM`은 쿼리 결과 집합을 메모리로 **가져오는 순서대로 1번부터 차례차례 번호를 부여**하는 가상(Pseudo) 컬럼입니다.
  • 데이터를 1건 가져와야 ROWNUM 1이 부여되고, 그래야 다음 데이터를 읽을 때 2가 부여됩니다.
  • 따라서 `WHERE ROWNUM > 1`이나 `WHERE ROWNUM = 2` 같은 조건을 주면, 1번을 읽지 않은 상태에서 2번 이상을 요구하므로 영원히 조건을 만족할 수 없어 데이터가 0건 추출됩니다. (단, 서브쿼리의 인라인 뷰를 활용해 밖에서 ROWNUM을 조회하면 가능합니다.)
Q12. NULL과 관련된 내장 함수의 특성을 설명한 것 중 가장 올바르지 않은 것은?
  • ① `NVL(expr1, expr2)` : expr1이 NULL이면 expr2를 반환하고, NULL이 아니면 expr1을 반환한다.
  • ② `COALESCE(expr1, expr2, expr3, ...)` : 나열된 인자 중 가장 먼저 만나는 NULL이 아닌 값을 반환한다.
  • ③ `NULLIF(expr1, expr2)` : 두 인자의 값이 같으면 NULL을 반환하고, 다르면 expr1을 반환한다.
  • ④ `ISNULL(expr1, expr2)` : SQL Server 전용 함수로, 두 인자의 값이 모두 NULL일 때만 특정 대체값을 반환한다.
상세 해설
정답은 ④입니다.
  • ①, ②, ③ (옳은 선지): NVL, COALESCE, NULLIF 함수의 동작 명세를 정확히 설명했습니다.
  • ④ ISNULL은 두 인자가 모두 NULL일 때만... (X): SQL Server의 `ISNULL(expr1, expr2)`은 오라클의 `NVL(expr1, expr2)`과 완벽히 똑같은 동작을 하는 함수입니다. 즉, 첫 번째 인자가 NULL일 때 두 번째 인자로 대체해 주는 함수입니다. 선지의 설명은 완전히 거짓입니다.
Q13. 다음 SQL 논리적 수행 순서(Execution Order)에 대한 원칙 중 가장 올바른 것은?
  • ① SELECT 절에 정의된 컬럼 별칭(Alias)은 WHERE 절과 HAVING 절에서 모두 사용할 수 있다.
  • ② GROUP BY 절이 수행된 이후에 SELECT 절이 수행되므로, GROUP BY에 참여하지 않은 일반 컬럼은 SELECT 절에 단독으로 올 수 없다.
  • ③ 쿼리의 맨 마지막에 실행되는 절은 출력 포맷을 결정하는 SELECT 절이다.
  • ④ FROM 절보다 WHERE 절이 먼저 수행되어 테이블의 크기를 줄인 후 조인(Join)이 발생한다.
상세 해설
정답은 ②입니다.
  • ② (옳은 선지): 수행 순서(FROM ➔ WHERE ➔ GROUP BY ➔ HAVING ➔ SELECT ➔ ORDER BY) 상 SELECT는 GROUP BY 이후입니다. 그룹으로 묶어버렸기 때문에 묶이지 않은 낱개 컬럼은 SELECT 절에서 출력할 수 없습니다. (반드시 SUM 등 그룹 함수로 묶어야 함)
  • ① (틀린 선지): WHERE, HAVING은 SELECT보다 먼저 수행되므로 SELECT의 별칭을 사용할 수 없습니다.
  • ③ (틀린 선지): 맨 마지막에 실행되는 것은 정렬을 수행하는 ORDER BY 절입니다.
  • ④ (틀린 선지): FROM 절이 가장 1빠따로 실행되어 테이블을 발췌합니다.
Q14. `EMP` 테이블에서 부서(`DEPT_NO`)별로 사원 수를 집계하되, 부서번호가 NULL인 데이터도 그룹화 대상에 포함시키고, 그룹 내 사원 수가 3명 이상인 부서만 조회하려는 쿼리이다. 올바르게 작성된 것은?

  • ② `SELECT DEPT_NO, COUNT(EMP_NO) FROM EMP GROUP BY DEPT_NO HAVING COUNT(EMP_NO) >= 3;`
  • ③ `SELECT DEPT_NO, COUNT(*) FROM EMP WHERE DEPT_NO IS NOT NULL GROUP BY DEPT_NO HAVING COUNT(*) >= 3;`
  • ④ `SELECT DEPT_NO, COUNT(EMP_NO) FROM EMP HAVING COUNT(EMP_NO) >= 3 GROUP BY DEPT_NO;`

  • ④ (틀린 선지): GROUP BY와 HAVING 절의 위치가 뒤바뀌었습니다. 표준 SQL 구조는 `GROUP BY ... HAVING ...` 순서입니다.
Q15. ANSI 표준 조인 구문 중 `USING` 절과 `NATURAL JOIN`의 공통된 제약사항으로 가장 올바른 것은?
  • ① 조인에 성공한 공통 식별자 컬럼을 SELECT 절에서 표기할 때, 테이블 별칭(Alias)이나 테이블명을 접두사(Prefix)로 붙일 수 없다.
  • ② 두 테이블 간에 이름과 데이터 타입이 같은 모든 컬럼을 찾아 자동으로 다중 조인을 수행한다.
  • ③ 조인 조건을 구체적으로 명시하기 위해 반드시 구문 끝에 `ON` 절을 수반해야 한다.
  • ④ OUTER JOIN 방식으로는 사용할 수 없고 오직 INNER JOIN 방식으로만 결합이 가능하다.
상세 해설
정답은 ①입니다.
  • ① (옳은 선지): `USING (DEPTNO)` 나 `NATURAL JOIN`을 통해 결합된 공통 컬럼은 합쳐진 하나의 공통 도메인으로 취급되므로, `A.DEPTNO` 처럼 특정 테이블의 별칭(Prefix)을 붙이면 문법 에러가 발생합니다.
  • ② (틀린 선지): 모든 공통 컬럼을 자동 조인하는 것은 `NATURAL JOIN`만의 특징입니다. `USING`은 개발자가 조인할 특정 컬럼을 명시적으로 선택합니다.
  • ③ (틀린 선지): 두 구문 모두 `ON` 절을 절대 혼용해서 쓸 수 없습니다.
  • ④ (틀린 선지): `LEFT OUTER JOIN USING (ID)` 형태로 OUTER 조인과도 정상적으로 혼용 가능합니다.
Q16. 다중행 연산자(Multi-row Operator)와 관련된 설명 중 가장 올바르지 않은 것은?
  • ① `IN` : 서브쿼리가 반환한 여러 결과 값들 중 단 하나라도 일치하는 값이 있으면 참(TRUE)이다.
  • ② `> ALL` : 서브쿼리가 반환한 모든 결과 값들 중 '최대값'보다 커야 참(TRUE)이다.
  • ③ `< ANY` : 서브쿼리가 반환한 결과 값들 중 가장 '최소값'보다 작아야 참(TRUE)이다.
  • ④ `EXISTS` : 서브쿼리의 결과 집합에 행(Row)이 단 1건이라도 존재하면 참(TRUE)이다.
상세 해설
정답은 ③입니다.
  • ①, ②, ④ (옳은 선지): IN(일치 여부), > ALL(모든 값보다 큼 = 최대값보다 커야 함), EXISTS(존재 여부)의 정확한 메커니즘입니다.
  • ③ < ANY 연산은 최소값보다 작아야 한다 (X): `ANY`(또는 SOME)는 서브쿼리의 결과 중 **'어느 하나라도'** 조건을 만족하면 참입니다. 따라서 `< ANY(10, 20, 30)` 이라면 이 중 가장 큰 값인 30보다만 작으면(예: 25) 10, 20보다는 크더라도 참이 성립합니다. 즉, `< ANY`는 '최대값보다 작으면 참'이라는 의미가 됩니다. 논리를 꼬아낸 고난도 문제입니다.

Q18. 집합 연산자인 `UNION`과 `UNION ALL`의 동작 메커니즘을 비교한 설명 중 가장 올바르지 않은 것은?
  • ① 두 연산자 모두 상/하위 쿼리의 컬럼 개수와 데이터 타입이 순서대로 일치해야 연산이 가능하다.
  • ② `UNION`은 두 집합 간의 중복된 행을 제거하여 유일한(Unique) 결과만 반환한다.
  • ③ 중복을 찾아내어 제거하기 위해 `UNION`은 데이터베이스 내부적으로 정렬(Sort) 혹은 해시(Hash) 연산을 필수적으로 유발한다.
  • ④ 두 쿼리의 결과에 원천적으로 중복 데이터가 절대 발생할 수 없는 구조라면, 옵티마이저가 이를 감지하여 `UNION`을 써도 정렬 연산을 생략하므로 `UNION ALL`과 동일한 성능을 낸다.
상세 해설
정답은 ④입니다.
  • ①, ②, ③ (옳은 선지): UNION과 UNION ALL의 필수 문법 제약과 UNION의 정렬(Sort) 오버헤드 메커니즘을 정확히 설명했습니다.
  • ④ 중복이 없으면 UNION도 정렬 연산을 생략한다 (X): 관계형 DB의 옵티마이저는 사용자가 `UNION` 키워드를 명시하면 데이터의 실제 중복 여부와 상관없이 무조건 중복 검사를 위한 막대한 정렬(Sort Unique) 작업을 수행해 버립니다. 따라서 중복이 없는 것이 확실한 집합(예: 1월 데이터와 2월 데이터 병합)이라면 무조건 `UNION ALL`을 사용하여 성능 저하를 피해야 합니다.

Q22. 소계 및 총계 기능을 지원하는 그룹 함수(Group Functions)인 `ROLLUP`과 `CUBE`의 차이에 대한 설명으로 가장 올바른 것은?
  • ① `ROLLUP(A, B)`는 결과 내에 A에 대한 부분 소계를 포함하지만, `CUBE(A, B)`는 B에 대한 소계만 포함한다.
  • ② `CUBE` 함수는 결합 가능한 모든 다차원 소계(2^N개)를 산출하므로 시스템에 부하를 많이 주지만, `ROLLUP`은 나열된 인자의 오른쪽에서 왼쪽 순서(계층형)로만 소계를 산출하여 부하가 덜하다.
  • ③ `GROUP BY ROLLUP(A, B)`의 결과와 `GROUP BY ROLLUP(B, A)`의 결과는 산출되는 데이터 건수와 소계 항목이 완전히 동일하다.
  • ④ 두 함수 모두 결과의 빈칸(Subtotal 행)을 자동으로 '소계'라는 문자열로 채워주는 기능을 내장하고 있다.
상세 해설
정답은 ②입니다.
  • ② (옳은 선지): `CUBE(A, B)`는 (A+B, A, B, 총계)의 모든 $2^2=4$가지 큐브 조합을 산출해 시스템 부하가 큽니다. 반면 `ROLLUP(A, B)`는 우측 인자부터 하나씩 벗겨내며 (A+B, A, 총계) 이렇게 3가지 단계적 소계만 구합니다.
  • ① (틀린 선지): CUBE는 A와 B 양쪽 소계를 모두 포함합니다.
  • ③ (틀린 선지): ROLLUP은 인자의 **'순서'**에 따라 소계 기준이 바뀌므로 (B, A)로 쓰면 A소계가 아니라 B소계가 나옵니다. 즉 결과가 완전히 다릅니다. (반면 CUBE는 순서를 바꿔도 똑같습니다.)
  • ④ (틀린 선지): 빈칸은 기본적으로 `NULL`로 출력되며, 이를 '소계'라는 문자로 치환하려면 사용자가 직접 `GROUPING` 함수와 `CASE` 문 등을 조합하여 쿼리를 짜야 합니다.
Q23. DCL(데이터 제어어) 명령을 통한 권한 부여 시 `WITH GRANT OPTION`의 동작 특성으로 가장 올바른 것은?
  • ① 권한을 받은 사용자는 해당 테이블에 대한 모든 종류의 DML, DDL 작업을 제약 없이 수행할 수 있게 된다.
  • ② 권한을 부여받은 사용자(A)가 제3자(B)에게 자신이 받은 권한을 다시 부여(전파)할 수 있는 자격을 가지게 된다.
  • ③ 권한을 준 관리자가 나중에 권한을 회수(REVOKE)하더라도, 이미 전파된 제3자의 권한은 독립적으로 계속 유지된다.
  • ④ 오직 시스템 권한(System Privilege)을 부여할 때만 사용할 수 있으며, 객체 권한(Object Privilege)에는 사용할 수 없다.
상세 해설
정답은 ②입니다.
  • ② (옳은 선지): `WITH GRANT OPTION`은 테이블 조회 등의 객체 권한을 넘겨줄 때, **"너도 다른 사람한테 이 권한을 나눠줄 수 있어"**라며 재부여 권리를 함께 넘기는 강력한 옵션입니다.
  • ③ (틀린 선지): 이 옵션으로 퍼져나간 권한은 **종속성**을 띱니다. 관리자가 A의 권한을 뺏으면(REVOKE), A가 B에게 나눠줬던 권한도 연쇄적으로(Cascade) 모두 소멸됩니다.
  • ④ (틀린 선지): 시스템 권한 전파 시에는 `WITH ADMIN OPTION`을 쓰고, 특정 테이블(객체) 권한 전파 시에는 `WITH GRANT OPTION`을 씁니다.
Q24. 조건에 따라 다른 값을 리턴하는 표준 SQL의 `CASE` 구문에 대한 문법 설명 중 올바르지 않은 것은?
  • ① Simple CASE 형식: `CASE 표현식 WHEN 비교값 THEN 결과 END` 구조로, 정확한 값의 일치(Equal) 여부만 평가한다.
  • ② Searched CASE 형식: `CASE WHEN 조건식 THEN 결과 END` 구조로, 내부 조건식에 부등호(>, <)나 다중 조건(AND, OR)을 자유롭게 사용할 수 있다.
  • ③ 모든 `WHEN` 조건을 만족하지 않을 때 반환할 기본값을 지정하기 위해 `ELSE` 절을 사용할 수 있다.
  • ④ `ELSE` 절을 생략한 상태에서 일치하는 `WHEN` 조건이 하나도 없다면, 쿼리는 즉시 런타임 에러를 발생시키고 실행을 중단한다.
상세 해설
정답은 ④입니다.
  • ①, ②, ③ (옳은 선지): CASE 문의 2가지 포맷(단순형/검색형)과 ELSE 절의 기본 동작을 잘 설명하고 있습니다.
  • ④ ELSE 생략 시 에러가 발생한다 (X): `ELSE` 절을 생략했는데 어떤 `WHEN` 조건에도 걸리지 않으면, 에러가 터지는 것이 아니라 조용히 `NULL` 값을 반환하고 정상적으로 쿼리 실행을 이어갑니다. 은근히 헷갈리기 쉬운 함정 선지입니다.
Q25. 데이터베이스 인덱스(Index)의 생성 및 활용에 대한 튜닝 관점의 설명으로 가장 올바르지 않은 것은?
  • ① 조건절(WHERE)에 자주 사용되며, 전체 데이터 중 카디널리티(분포도)가 높은(고유한 값이 많은) 컬럼에 인덱스를 생성하는 것이 가장 유리하다.
  • ② 여러 컬럼을 묶어 결합 인덱스(Composite Index)를 생성할 때는 조건에 가장 자주 사용되고 변별력이 높은 컬럼을 인덱스의 '선행 컬럼(앞쪽)'에 배치해야 성능이 좋다.
  • ③ 인덱스가 생성된 컬럼이라도 `WHERE col != 10` 처럼 부정형 연산자를 사용하면 옵티마이저가 인덱스 스캔을 포기할 확률이 높다.
  • ④ B-Tree 인덱스 구조상 데이터의 수정(UPDATE) 작업 시에는 리프 블록만 업데이트하면 되므로 인덱스가 없는 테이블보다 수정 속도가 훨씬 빠르다.
상세 해설
정답은 ④입니다.
  • ①, ②, ③ (옳은 선지): 인덱스 선정 기준(카디널리티 ⬆), 결합 인덱스 선행 컬럼의 중요성, 부정형 연산의 풀 스캔(Full Scan) 유발 등 핵심 튜닝 지식을 잘 나열했습니다.
  • ④ 인덱스가 있으면 UPDATE 속도가 빠르다 (X): 인덱스는 철저히 '조회(SELECT)' 속도를 위해 존재합니다. 데이터가 수정(UPDATE)되거나 삽입/삭제(DML)될 때마다, 원본 테이블뿐만 아니라 인덱스 나무(B-Tree) 데이터도 쪼개고 옮기며 실시간으로 동기화(정렬 유지)해야 하므로 오히려 수정 속도(오버헤드)가 비약적으로 느려집니다.
Q26. SQL 내에서 사용되는 가상 컬럼 및 모조 속성(Pseudo Column) 중, 각 테이블 행들의 디스크 상의 물리적인 실제 저장 주소를 가리키는 유일하고 고유한 식별자는?
  • ① ROWNUM
  • ② ROWID
  • ③ OID (Object Identifier)
  • ④ SEQUENCES
상세 해설
정답은 ② ROWID입니다.
  • ② (옳은 선지): `ROWID`는 오라클 데이터베이스 내에서 해당 데이터 행이 디스크의 몇 번째 블록, 몇 번째 슬롯에 저장되어 있는지를 나타내는 고유한 '물리적 주소값'입니다. 인덱스는 바로 이 ROWID를 가리키고 있어 초고속 검색이 가능합니다.
  • ① (틀린 선지): `ROWNUM`은 물리적 주소가 아니라 추출 시점에 논리적으로 부여되는 임시 번호입니다.
Q27. `SELECT` 절 내부에서 단일 값을 반환하는 '스칼라 서브쿼리(Scalar Subquery)'를 사용할 때 얻을 수 있는 데이터베이스 내부 성능 튜닝 효과는?
  • ① 메인 쿼리와의 복잡한 조인(Join) 연산을 완전히 대체하므로 항상 실행 속도가 가장 빠르다.
  • ② 메인 쿼리의 데이터 한 건당 서브쿼리를 반복 실행하는 구조적 비효율을 피하기 위해, 내부적으로 입력값과 출력값을 메모리에 캐싱(Caching)하여 성능을 최적화한다.
  • ③ 옵티마이저가 스칼라 서브쿼리를 자동으로 인라인 뷰(Inline View)로 해체하여 파티션 테이블로 변환한다.
  • ④ 서브쿼리 결과가 여러 건 반환되더라도 쿼리 에러를 내지 않고 첫 번째 값을 자동으로 골라준다.
상세 해설
정답은 ②입니다.
  • ② (옳은 선지): 스칼라 서브쿼리는 메인 쿼리 행마다 반복 실행되므로 부하가 커 보이지만, 오라클은 스칼라 서브쿼리 캐싱(Scalar Subquery Caching)이라는 메커니즘을 작동시킵니다. 이전에 동일한 파라미터로 서브쿼리를 돈 적이 있다면 DB를 뒤지지 않고 메모리에 저장된 값을 즉시 꺼내어 반환하므로, 중복 데이터가 많은 환경에서 조인보다 훨씬 뛰어난 성능을 발휘하기도 합니다.
  • ① (틀린 선지): 조인보다 항상 빠른 것은 아닙니다. 데이터 건수가 너무 방대하면 캐싱 오버헤드가 발생해 조인보다 느려집니다.
  • ④ (틀린 선지): 스칼라 서브쿼리는 2건 이상 반환 시 무조건 에러(ORA-01427)가 발생합니다.
Q28. 아래 보기와 같이 `EMP` 테이블 구조를 복사하여 새로운 빈(Empty) 테이블 `EMP_BAK`를 생성하고자 할 때, 가장 적절한 표준 SQL 구문은?

  • ① `CREATE TABLE EMP_BAK AS SELECT * FROM EMP;`
  • ② `CREATE TABLE EMP_BAK AS SELECT * FROM EMP WHERE 1 = 0;`
  • ③ `COPY TABLE EMP TO EMP_BAK WITHOUT DATA;`
  • ④ `ALTER TABLE EMP CLONE TO EMP_BAK;`
상세 해설
정답은 ②입니다.
  • CTAS(Create Table As Select) 기법을 묻는 문제입니다.
  • 기존 테이블의 뼈대(구조)만 빼오고 데이터는 제외하려면, 서브쿼리의 `WHERE` 절에 절대 참(TRUE)이 될 수 없는 거짓(FALSE) 조건 (예: 1=0 또는 1=2)을 부여하면 됩니다. 그러면 데이터는 0건이 반환되지만 컬럼 구조는 통과되어 빈 테이블이 이쁘게 생성됩니다.

Q29. 옵티마이저(Optimizer)의 실행 계획을 제어하기 위해 SQL 문장 내에 명시하는 힌트(Hint) 문법으로 올바르게 작성된 것은? (Oracle 기준)
  • ① `SELECT /* HINT(INDEX_EMP_01) */ emp_name FROM emp;`
  • ② `SELECT --+ INDEX(emp idx_emp_01) emp_name FROM emp;`
  • ③ `SELECT /*+ INDEX(emp idx_emp_01) */ emp_name FROM emp;`
  • ④ `SELECT /*+ FORCE_INDEX = idx_emp_01 */ emp_name FROM emp;`
상세 해설
정답은 ③입니다.
  • 오라클에서 옵티마이저에게 힌트를 전달하는 표준 주석 문법은 `/*+ 힌트내용 */` 입니다. 반드시 주석 시작 기호 직후에 **플러스(+)** 기호를 붙여야 일반 주석과 구별되어 옵티마이저가 힌트로 인식합니다.
  • 또한 인덱스 힌트 작성 시에는 `INDEX(테이블별칭 인덱스명)` 구조로 작성해야 합니다. 문법이 1글자라도 틀리면 DB는 힌트를 에러 처리하지 않고 일반 주석으로 무시해 버리므로 주의해야 합니다.
Q30. 데이터의 정합성을 보장하기 위해 적용하는 무결성 제약조건 중, "사용자가 입력한 값이 1에서 100 사이의 범위에 속해야 한다"와 같은 사용자 정의 논리를 테이블 자체에 강제하는 제약조건은?
  • ① PRIMARY KEY
  • ② CHECK
  • ③ FOREIGN KEY
  • ④ DEFAULT
상세 해설
정답은 ② CHECK입니다.
