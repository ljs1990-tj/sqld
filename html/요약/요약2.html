📊 SQLD 2과목: SQL 기본 및 활용 (Part 1)

DDL/DML 차이, 트랜잭션, NULL 특성, 실행 순서 완벽 정리

1. SQL 명령어와 데이터 삭제 방식의 차이

  • DDL (데이터 정의어): CREATE, ALTER, DROP, TRUNCATE ➔ Auto Commit (롤백 불가)
  • DML (데이터 조작어): SELECT, INSERT, UPDATE, DELETE ➔ 트랜잭션 대상 (롤백 가능)
  • TCL (트랜잭션 제어어): COMMIT, ROLLBACK, SAVEPOINT
  • DCL (데이터 제어어): GRANT, REVOKE
DROP (DDL) 테이블의 구조(스키마)와 데이터를 모두 완전 삭제합니다. 복구가 불가능합니다.
TRUNCATE (DDL) 테이블의 구조는 남기고 데이터만 모두 삭제합니다. 로그를 남기지 않아 속도가 빠르며 롤백이 불가합니다.
DELETE (DML) 데이터만 삭제합니다. WHERE 절로 조건을 줄 수 있으며, 로그를 남기므로 ROLLBACK이 가능합니다.

2. 트랜잭션의 4대 특성 (ACID)

데이터베이스의 논리적 연산 단위인 트랜잭션이 반드시 지켜야 할 4가지 특성입니다.

  • 원자성 (Atomicity): All or Nothing. 트랜잭션 내의 작업은 모두 성공(Commit)하거나 모두 실패(Rollback)해야 합니다.
  • 일관성 (Consistency): 트랜잭션 실행 전후로 데이터베이스의 무결성 제약조건은 항상 모순 없이 일관되어야 합니다.
  • 고립성 (Isolation): 실행 중인 트랜잭션 중간에 다른 트랜잭션이 끼어들어 데이터를 훼손할 수 없습니다.
  • 지속성 (Durability): 성공적으로 완료(Commit)된 트랜잭션의 결과는 시스템 장애가 발생하더라도 영구적으로 보존되어야 합니다.

3. NULL의 특성 및 관련 함수

  • NULL의 연산: 숫자 연산(+, -, *, /)에 NULL이 포함되면 결과는 무조건 NULL입니다. (예외: 오라클에서 문자열 결합 || 연산 시 NULL은 무시됨)
  • 집계 함수와의 관계: SUM, AVG, MAX, MIN 등은 NULL인 행을 제외하고 연산합니다.
    ※ 단, COUNT(*)는 NULL을 포함한 테이블의 전체 행 수를 반환합니다. (COUNT(컬럼명)은 NULL 제외)
NVL (Oracle) NVL(col, 값) : 컬럼 값이 NULL이면 지정한 값을 반환합니다. (SQL Server는 ISNULL)
NULLIF NULLIF(A, B) : A와 B가 같으면 NULL을 반환하고, 다르면 A를 반환합니다.
COALESCE COALESCE(A, B, C...) : 괄호 안의 인자 중 최초로 NULL이 아닌 값을 찾아 반환합니다.

4. SQL 논리적 수행 순서와 GROUP BY

💡 논리적 수행 순서 (매회 출제)
FROM (발췌) ➔ WHERE (필터) ➔ GROUP BY (그룹핑) ➔ HAVING (그룹필터) ➔ SELECT (출력) ➔ ORDER BY (정렬)
  • 별칭(Alias) 사용 주의: SELECT 절보다 먼저 수행되는 WHERE, GROUP BY, HAVING 절에서는 SELECT 절에서 만든 별칭을 사용할 수 없습니다. (오직 맨 마지막에 실행되는 ORDER BY에서만 사용 가능)
  • GROUP BY 특징: GROUP BY 절에 명시되지 않은 일반 컬럼은 SELECT 절에 단독으로 올 수 없습니다. (반드시 SUM, COUNT 같은 집계 함수로 묶어야 함)
  • 정렬(ORDER BY) 시 NULL 위치:
    • 오라클(Oracle): NULL을 무한히 큰 값으로 취급 ➔ 오름차순(ASC) 시 맨 마지막에 출력
    • SQL Server: NULL을 가장 작은 값으로 취급 ➔ 오름차순(ASC) 시 맨 처음에 출력
